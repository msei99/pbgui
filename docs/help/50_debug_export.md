# Debug export

About displays the installed PBGui version and API serial on this page as on other PBGui pages.

Open **Information → Debug export**. This is the common support entry point for every PBGui area: PB7/PB8 Run, Backtest, Optimize, AI Loops and chat transport, Vast workers, Jobs, Market/Coin Data, VPS/monitoring, Cluster, Services, Logging, DB Tools, dashboards, strategy/Pareto explorers, balance/limits and transfer/profit-sweep workflows. Registered API routes and service/native log sources are discovered automatically rather than requiring a separate collector for each page.

Click **Collect debug report**. Depending on the selected attachment contents, the report includes versions, installed dependency versions, OS/Python/CPU/GPU and resource information, API serials, operational queue/runner/cache records, your own AI Loop and conversation/research metadata, quantitative native backtest analyses, local database health/schema metadata and bounded service/job log excerpts. It performs no rental, exchange or VPS request, starts no bot/job, and changes no configuration. GPU metadata uses a bounded local `nvidia-smi` query when available. No background debug mode remains running.

AI Loop detail windows also provide **Debug export**. That entry prioritizes the selected owned Loop, including its termination, job failures, exact-comparison assessments, per-report completion and required metric evidence. Additional application areas remain available through Report contents.

**Summary** shows collected sources, counts, file tails, missing/invalid sources and limits. **Report preview** uses the full available page height and groups the same snapshot into System and versions, Operational records, Log excerpts, Databases, Coverage and limits, Browser, and Report metadata. Filter sources, select an entry and expand individual fields. Source lists and nested lists show 40 entries per page; long text is shown in 4,000-character sections. Closing a field releases its rendered details. These display limits do not remove data from the download. The selected category, source, source-list page and filter are restored after reload and recollection. **Download report** saves that same JSON locally. Send the downloaded file to support yourself; PBGui does not upload it to an external support service automatically. The prepared report exists only in browser memory; after reload collect a new one. Tabs, selected Loop context and sidebar geometry preserve navigation.

Credential/auth/session files, private keys, configuration contents, chat messages/prompts, raw market/trade datasets and database rows are excluded. Operational fields are selected and strings are redacted; URLs and home paths are removed. Other users' AI Loop/conversation files are excluded. Database checks are immutable read-only snapshots: pending WAL contents are not inspected, and the report marks this limitation. Shared service logs follow the same authenticated access boundary as Logging Monitor.

Collection is bounded to 400 sources, 8 MB of input and a 12-second scan budget; each log contributes at most its last 16 KB / 120 lines, and oversized records are omitted. Scans, lists and nested records have additional bounds, reported where applicable. Missing optional software is shown as unavailable. This is broad technical coverage, not an unrestricted dump of all application data. For an old failure whose logs have already rotated away, reproduce it and collect again; the export cannot recover deleted evidence.

Browser diagnostics also include browser/viewport information and up to 50 recent JavaScript error locations across pages. Only type, local script filename, line/column and time are retained in session storage; messages, stacks, cookies and page query strings are not stored.

## Report an issue on GitHub

Choose **Report issue on GitHub** in the sidebar. PBGui uses the existing report, or collects one automatically if none is ready. There is no separate collection button in the issue dialog. The dialog initially fills the browser viewport with a small margin. Description fields and public preview/attachment options appear side by side on wide screens and stack on narrow screens. The header and action footer remain visible; the body scrolls when necessary. The dialog remains movable/resizable and remembers your geometry. Enter a title and describe the problem; reproduction steps and expected behavior are optional. Expand **Public issue preview** to check the public description. Diagnostic contents are inspected in the existing **Report preview** on the Debug export page, outside the issue dialog. Keep passwords, account details and other private information out of the public description.

Use **Review GitHub publication** to create the finished issue directly from PBGui after reviewing the public text and attachments. See Direct GitHub publication below. The alternative **Prepare encrypted attachment → Continue to GitHub** still downloads a ZIP and opens a prefilled GitHub form; attach the ZIP and submit there. That alternative needs no GitHub token in PBGui. A GitHub account is required for either route. Nothing is published without your explicit action.

The ZIP contains only an encrypted envelope; ordinary archive software cannot decrypt it. Compression happens before AES-256-GCM encryption; the random encryption key is wrapped with the support team's RSA-OAEP-SHA256 public key. Only holders of the separate private key can decrypt the report. The existing plain JSON download remains available for direct support conversations; do not attach that unencrypted JSON to a public issue if it contains private information.

Encryption happens on your own PBGui backend, not a central support server. Reports are limited to 12 MiB before compression and attachments to 24 MiB. The browser-form alternative also limits descriptions to fit the issue link; direct publication supports longer analysis. Description/report changes invalidate prepared attachments. Closing revokes the local download link. Reload preserves navigation and geometry, while unsaved descriptions and the collected snapshot are discarded. Direct-publication reviews and receipts are restored separately from encrypted server storage.

## Investigate with AI

Open **Draft with AI**, describe the problem in any language and use **Investigate with AI**. A diagnosis is useful on its own: you do not need to apply a draft or publish an issue. **Generate English draft** remains the simpler text/image formulation action.

Choose **Send selected report contents** under **Diagnostic data for AI** to send the currently selected bounded/redacted diagnostic areas; the default sends none. If needed, PBGui collects the report on this explicit action. **PBGui source inspection** separately permits or disables inspection of installed application code. Screenshots require their existing individual AI selections. Investigation may send these approved data and code snippets to your selected AI provider; normal provider usage applies.

The assistant can list/search installed source, read numbered source slices and inspect selected diagnostic records/log excerpts. Source includes PBGui Python/API/frontend code, excluding runtime data, configuration files, hidden files, vendors and symlinks. Reads are bounded and redacted, with source fingerprints and evidence IDs. The model is pinned for at most six steps within five minutes. It cannot run tests, execute commands, modify code/configuration, operate services or publish. Results distinguish observations, evidence, suspected causes, proposed fixes and validation still required; follow-up questions identify missing evidence. Add answers to the free-text input and investigate again if needed. A diagnosis is not an executed reproduction or verified patch.

**Apply English draft** optionally fills the issue fields and **Analysis and proposed fix (public)**. That analysis is editable and included in the public preview. Check it for accuracy and private information before publication.

## Direct GitHub publication

Choose **Review GitHub publication**. Connect your own account once using a GitHub personal access token; the dialog links to GitHub's token creation page with `public_repo`. Use an expiry and only the required scope. A classic token supports reporting to a public project where you are not a member and using your own public asset repository; GitHub documents the corresponding fine-grained token limitations in [Managing personal access tokens](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens). PBGui verifies the account and stores the token encrypted in owner-only local files, never in browser storage or the AI context. Disconnect removes the local token; it does not delete issues or cloud assets.

**Prepare publication review** builds the exact public body and encrypted attachment without any GitHub write. The review shows title, target `msei99/pbgui`, your GitHub account and any public asset repository. If attachments are present, publishing creates/uses the public repository `<your-account>/pbgui-support-assets` and a release for this report. The diagnostic ZIP stays encrypted. Screenshot buttons labelled **Publish screenshot … publicly** are a separate choice from AI analysis, initially unselected. Selected images are uploaded publicly and embedded in the issue; unselected images remain only in the encrypted ZIP. Before approval the exact selected public images are shown through authenticated local previews, including after reload. Existing private repositories are never made public automatically.

After checking the public preview and the reviewed images, click **Publish reviewed issue**. PBGui uploads the reviewed files through GitHub's official release-asset API, creates the issue, then offers **Open published issue**. Files stay out of Git history. No support server, shared maintainer token or registration service is involved. Feature requests without files create only an issue. Preparing another review or editing its inputs invalidates an unapproved local review.

Publication continues after browser closure because it was explicitly approved. Encrypted local receipts survive API restart; repeating the same approval does not create another issue. An unconfirmed issue POST offers **Check previous publication**, which searches its unique marker instead of posting again. Partial uploads may remain in your asset repository if publication fails; inspect the retained review and manage those releases on GitHub. Pending large reviews expire after 30 minutes (four globally at once); up to 128 small completed/unconfirmed receipts are retained. **Discard local review** removes an unapproved local payload without deleting remote resources. Review IDs/navigation alone are kept in the browser; tokens, snapshots and images are not.

Coverage budgets reserve at least one quarter of source/byte capacity for logs, cap each operational area at 40 records / 1 MB, and prioritize the selected Loop. This prevents one large queue or chat archive from consuming the whole report. Recent files are read first; the two newest rotated log backups are eligible too.

## Draft with AI

Click **Draft with AI** near the top of the form to open **Describe your problem or idea (any language)**. You can start with an empty issue form. Write freely in that input, then click **Generate English draft**. Opening the input does not contact the AI; generation becomes available when text is present. An existing description is copied into an empty AI input as a starting point. PBGui uses the model last selected in AI Chat (ChatGPT or OpenCode Go/Zen). Select and connect a model there first if none is available; the structured OpenRouter/Jev model is not used for drafting. Normal provider usage applies. The AI input, existing title/optional fields and issue type are sent to that provider, without debug data, error context or conversation history. Do not include secrets in your text.

Attached screenshots appear as selectable thumbnails in the AI input area. None are selected initially. Select the images the AI should inspect before generating the draft. **Selected images are sent to your AI provider** as visual input; review them for private information first. The AI is instructed to identify the visible PBGui page/panel, such as Dashboard / Profit and Loss, and use that context in the English issue. The selected model must support image input; if the request fails, choose an image-capable model in AI Chat or deselect the images. There is no automatic retry without images or model substitution. The combined request is limited to 12 MiB. Selecting, removing or adding images discards pending suggestions. AI image selection is kept only in memory and does not publish an image or change the encrypted attachment. Public image sharing requires the separate GitHub selection and final publication approval.

The AI translates prose into English and improves its structure while preserving code and quoted errors. It is instructed to leave missing facts and optional details unspecified. Review **English AI draft**, then click **Apply English draft** to replace the form fields. Nothing is published automatically. Editing the source text, changing issue type, closing the dialog or **Cancel AI draft** cancels pending drafting and discards suggestions. Errors and timeouts keep your original text. Applied text remains editable; check the public preview before submitting on GitHub.

For ChatGPT image input, your own PBGui backend creates private temporary image files and removes them after the request, including on failure or cancellation. No permanent screenshot archive is kept by PBGui for AI drafting. The selected AI provider's processing and retention terms apply to transmitted images.

## Feature requests

In the GitHub dialog, choose **Feature request** under **Issue type**. Describe what you would like and why; a suggested solution and alternatives are optional. The public preview and GitHub description use these feature-specific headings. **Continue to GitHub** opens the prepared request for you to review and submit.

Feature requests default to **No debug report**. Choose **Include debug report** if diagnostics help explain the request. Screenshots can be added either way and always require an encrypted attachment. Without diagnostics, that attachment contains only screenshots and basic report/version metadata. Changing issue type preserves your draft text and invalidates any previously prepared attachment. Reload remembers the issue type, but clears draft text and screenshots. Reports opened directly from an error default to **Problem**.

## Screenshots

In the GitHub issue dialog, use **Add screenshots**, drop image files onto the dialog, or paste an image from the clipboard. Thumbnails let you check and remove images before preparing the attachment. Screenshots default to the encrypted ZIP and are absent from the ordinary diagnostic JSON download. Sharing with AI and publishing an image in the issue are separate explicit selections. Without public image selection, the browser-form description includes only their count.

You can add up to five PNG, JPEG or WebP images, each at most 4 MiB and 12 million pixels. The selected diagnostics and encoded images together must fit the 12 MiB report limit. Images are not automatically redacted: check them before sharing. Screenshot drafts stay in browser memory while the dialog is closed and reopened, and disappear on reload. Adding or removing an image invalidates the prepared attachment.

## Select attachment contents

Use **Report contents** in the sidebar or **Attachment contents** in the GitHub dialog. Both controls share the same selection and show the selected uncompressed JSON size. System/version metadata is always included. A reported error context is always included when the report was opened from an error. Browser diagnostics, service/job data, AI Loops/chat metadata, backtests, optimization, bot runtime, market/coin data, VPS/monitoring/cluster, Vast, database health, other application data and collection details can be toggled independently. Unknown source names are grouped under Other application data.

A manual report defaults to all bounded, redacted diagnostic areas. A report opened directly from a recognized error defaults to browser/service diagnostics, collection details and the affected area with related evidence: AI Loops also include optimization/backtests/Vast, optimization includes backtests/market data, backtests include market data, and bot runtime includes VPS/market data. Unknown error areas fall back to all areas. You can deselect areas. Legacy minimal selections reset once to these defaults; new explicit selections are preserved per report context. Preview, plain JSON download and encrypted ZIP all use the same selected snapshot. Changing the selection invalidates a prepared attachment. Choices persist per report context in the browser tab; report contents and error messages are never saved in browser storage. Collection still scans the bounded local source set once; selection controls what is included in the attachment, rather than rerunning the scan for every toggle.

## Report directly from an error

Shared error dialogs offer **Report this problem**. A failed AI Loop detail window offers the same action. Error notifications and uncaught JavaScript errors expose **Report error** in the navigation bar for the most recent error. These actions open the report workflow in a new tab, preserving the original page and its edits. If the browser blocks the new tab, click **Open report** after preparation.

PBGui sends the error context only to its own authenticated local API. It redacts the message/detail and holds the context in a bounded, owner-specific in-memory cache for ten minutes (128 contexts maximum, lost on API restart). The URL contains only an opaque context ID; error messages never enter URLs or browser storage. The report dialog collects diagnostics, suggests the related scope and fills a generic title. Write your own public description: error evidence is included in the encrypted attachment and is not automatically copied into the public issue. An expired/unavailable context is reported explicitly; reopen the error report action to create a new one. Nothing is published automatically. A completely stopped API cannot handle the action; restart PBGui and use the ordinary Debug export entry instead.
## Direct chat alternative

You can also describe bugs and feature requests directly in **AI Chat**, investigate relevant redacted diagnostics and installed code, and approve the English GitHub issue there. The GitHub connection is shared with this dialog. See **AI Chat** in Help for the direct workflow; Debug export remains available for detailed report and screenshot selection.
