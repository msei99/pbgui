# v2.04.13

## Fixes
- Limit Vast input exports to the base/active-scenario date envelope plus native PB8 optimizer warmup, instead of copying every available historical day. Requeue rebuilds the package with the corrected selection; frozen jobs remain unchanged. Fail preparation if dates or native warmup cannot be determined.
- Keep Vast SSH and rsync stop checks and progress callbacks running after output pipes close, until the child actually exits. Continue draining SSH diagnostics to prevent a full stderr pipe from blocking completion; cover metadata submission, job/rental stop, and child cleanup with isolated subprocess tests.
- Compress large Vast transfer manifests and show metadata submission progress separately from candle-file synchronization, retaining compatibility with uncompressed framed senders.
- Include outdated local Vast run/guard supervisors in the shared Restart button. Verify process ownership and startup serial, restart their systemd units before the API, and resume persisted jobs without ending the rental.
- Fix Vast file synchronization hanging during remote preparation: frame metadata with an explicit length so the receiver does not wait for SSH stdin EOF.
- Prevent saving or queueing optimizer configs with unapplied visual windows or active windows outside the current base dates; keep workload estimates tied to actual training scenarios.
- Save & Queue uses the validation result for its captured cloud config even if background validation advances; transport errors retain their actual reason.
- PB8 parameter help opens only over field labels, never when focusing or editing input values, including calendar date fields.
- Keep confirmed navigation restarts visibly in progress, prevent duplicate requests, and verify a new API instance before returning to the current page. Lost responses are checked automatically without resubmitting the restart.
- Optimizer date fields overwrite existing digits instead of inserting extra year digits; selection replacement and paste remain available.
- Applying graphical scenario windows corrects generated names after role/date changes and retains normalized window metadata, including multiple distributed holdouts for validation.
