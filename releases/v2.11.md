# v2.11

- Stabilize isolated browser regression checks for cold coin-selection timing and legitimate chart-history prefetch timing while retaining responsiveness and viewport assertions.

- Preserve Vast convergence preferences for native optimizer jobs without an intent file; keep malformed existing intent files as errors.

- Fix PBGui update status after selecting a fork: the background collector always checks the official repository, and hosts with a different configured source show a neutral custom-source status. Agent metadata reports only a bounded source classification, never a Git URL or credentials. Legacy fork cache heads are discarded when the new official check starts.

- Restrict direct PB8 version-install requests to official or credential-free repositories configured on the controlling master. PBGui version installs now remember their selected repository in the target checkout; normal PBGui updates follow that repository and current branch. The official PBGui source remains selectable after switching the controlling master to a fork.

- Fix TOP dashboards configured for 1,000 symbols returning HTTP 422 and showing "Data unavailable". Accept up to 1,000 symbols in the API and match the TOP controls in the viewer and editor.

- Allow choosing older commits from `master` or another PB8 branch in PB8 Versions on masters and VPS hosts. Load history in batches or enter a full SHA; pin the existing controller-built wheel workflow to the selected commit and restore the choice after browser reload.

- Allow installing an older PBGui commit from a selected branch in PBGui Versions. Load commit history in batches or enter a full commit SHA, preserve the selected commit across browser reloads, and verify branch ancestry before changing the target checkout.

- Replace PBGui branch/commit controls on master and VPS pages with the searchable, paginated version table used for PB8. Sort by branch-head commit time, retain repository/search/selection/page across live updates and reloads, and allow installation from credential-free remotes configured on the controlling master through the existing PBGui switch playbooks.

- Show PB8 versions on masters and VPS hosts in a searchable, paginated branch table sorted by the branch head's commit time. Preserve source, search, selection, and page across live updates and browser reloads; continue showing names when commit dates are unavailable.

- Fix PB8 Versions remaining on "Loading versions..." after a VPS Manager WebSocket interruption: discard abandoned branch requests, time out unanswered lookups, show the lookup error inline and retry automatically.

- Complete the remaining wheel entry points: Linux updates no longer reinstall Rust on cleaned VPS hosts; the legacy PB7 Python 3.12 playbook delegates to the central wheel update; fresh local and remote GUI master installs use source-bound PB7/PB8 wheels, verify installed binaries, write receipts and seed reusable master caches. Remote installation transfers both bundles from the controlling master and pins PB8 to the bundled commit. Updated installer progress and EN/DE VPS guidance. No remote host was changed by this code update.

- PB7 and PB8 master/VPS updates now share source-bound controller-built wheels, including combined updates, setup and PB7 branch switches. PB7 VPS updates no longer install Rust or compile locally; validated wheel receipts mark legacy source installs for update. A VPS removes bot Rust targets, its unused Rust/Cargo toolchain and the obsolete Ubuntu rustup package only after every installed PB7/PB8 runtime is verified as a wheel installation. An unrelated toolchain or Cargo command keeps shared Rust tools in place.

- Fix false PB7/PB8 "upstream stale" warnings when the shared Passivbot remote has more than 1,000 branches: scan all returned refs for the default branch while keeping the cached head list bounded at 1,000.

- Harden wheel updates: the controlling master resolves the official PB8 head or uses the authenticated branch selection, and the target must confirm the same commit before a native build. The master creates its own source archive; branch switches may build user-selected forks. Verify receipt paths before stopping bots, rebuild corrupt cache entries, and recover PBRun after failed PB7 updates and branch switches. Combined PBGui/PB7 updates skip PB7 runtime changes when the checkout and installed wheel receipt match; shared PB7 installation tasks cover master and VPS updates.

- Fix PB8 retries after an interrupted first install: the tracked-change guard now applies only to version switches on a checked-out repository, so normal Update PB8 restores upstream `master` again. Restore the PB7 remote-URL origin hint and ignore late version-list responses without a loaded host detail.

- Replace PB8 branch plumbing with a version picker on masters and VPS: choose the official Passivbot repository or a credential-free fork already configured on the controlling master, select a branch, and install. The branch list loads automatically and the selected source/version survive browser reloads. First-time PB8 installs can use a selected branch; the controlling master resolves and builds the wheel, then transfers it to the target.

- Keep Convergence & Stagnation visible when stopping is disabled. Standalone uploading/running jobs can enable/disable and tune their stopping policy directly in the log, preserving unsaved edits through automatic updates.

- Authenticated strict settings edits reset the observation window at the next verified snapshot, retain optimizer inputs and rental limits, and reject stale edits, research trials and jobs already stopping. Settings writes and snapshot observations share one cross-process lock. Updated EN/DE help and browser asset version.

- Fix VPS Manager detail update warnings for apt-deferred packages: count installable upgrades, retain deferred totals in the status/details, and highlight Update Linux only for actionable upgrades/installations/removals on master and VPS views. Preserve stale/unavailable warnings and automatic in-place updates; update EN/DE help.

- Fix completed VPS updates remaining Task Running in Overview: use current-run terminal recap consistently, reconcile persisted state automatically under the host launch lock and generation-checked inventory transaction, persist the actual Ansible runner result, and ignore superseded callbacks. Missing current logs never inherit a previous alias/buffer recap. Updated EN/DE help and API restart serial.

- Replace the initial Docker wheel builder with a native build on the controlling PBGui master. Master and VPS update playbooks use checked binary installs; full/GPU dependency selection happens before runtime changes. Target masters import verified bundles into their own cache for later distribution. Auditwheel validates the actual glibc ABI.

- Fix VPS Manager master-update progress logs changing task names during an active run: mark the accepted run as starting before inventory refresh and bind Ansible events to its original command. A PB7 wheel build could previously continue successfully while its output appeared under the prior PB8 log, leaving the PB7 log window at the start banner.
