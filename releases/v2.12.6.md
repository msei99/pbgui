# v2.12.6

## PB9 Run: move through the existing Save action

- Fix changing an enabled PB9 instance to another host being rejected with
  "Disable the PB9 instance and wait for its confirmed stop before moving it".
  Select the new host and Save. PBGui validates the requested config and target,
  publishes a disabled source generation, waits for its confirmed stop, then
  saves the requested target through the existing guarded bundle transaction.
- Use the existing shared PB7/PB8/PB9 Cluster activation transport for editor
  saves and both handover phases. Periodic Cluster reconciliation remains the
  fallback when immediate delivery is unavailable.
- Retain the disabled source assignment in Cluster state. Remote stop evidence
  must be fresh and match that exact disabled version, including after a retry
  or backup pruning. Missing desired-state materialization, API cancellation
  and concurrent saves cannot authorize target activation.
- Wait at most 30 seconds for stop confirmation. If confirmation is unavailable,
  keep the instance disabled, preserve the editor draft and acknowledge the
  disabled version so Save can be retried. Save conflicts remain visible in the
  shared dialog instead of disappearing in a short-lived notification.
- Reopen an already visible log viewer after a successful save so it follows the
  saved assignment, including when newer edits remain unsaved. Keep PB8's
  existing Save behavior and native account/process checks in place.

## Validation and rollout

All 288 focused offline tests passed; release-metadata and help-coverage checks
also passed. The tests cover both move directions, invalid requests before Stop,
stale generation evidence, retry after timeout and backup pruning, cancellation,
concurrent writes, and deferred desired-state materialization. Native Chromium
checks reproduce local Log → Home → edit host → Save → remote Log using the
shared editor and LogViewerPanel, and verify retry-state and draft preservation.
PB8 and Cluster regressions are included. All activation transport in these
tests is mocked; no real bot is moved or stopped.

Fable assisted with the handover safety plan. Its separate bounded code-review
attempt did not return a completed verdict; validation is based on the source
review and focused tests described above.
