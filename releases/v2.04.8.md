# v2.04.8

## Interim fix — GPU / Vast.ai work in progress

This release is an interim fix for the current GPU / Vast.ai workflow. It improves rental recovery, host selection, progress reporting and performance history, but does not complete the interface redesign.

Further work is required to clean up Settings and move GPU / Vast.ai management into its own clearly separated area. GPU rentals, host management and performance views are still mixed into Settings in this version; this organization is temporary.

Performance history starts collecting when the updated API is running. Initial workload inspection can take time for large input bundles; historical measurements are only available where previously observed data exists.

## Changes

- Add private SQLite Vast Performance History with an API-owned 60-second collector, retained minute counters/utilization/phases, workload fingerprints from frozen config/data/software, and exported-data complexity metadata. Add sidebar browsing, strict same-workload comparisons, local speed charts, time-weighted rates and explicit cost estimates; retain history independently of queue deletion. Fix overlapping log tails losing the earlier throughput baseline.

- Add Vast log statistics from timestamped native optimizer counters with a bounded, persistent observation history: proxy/minute, exact/minute, cumulative proxy/exact workload and estimated exact evaluations per rental USD. Show interval/sample age, suppress stale live rates, and retain clearly labelled final interval statistics without including provisioning or upload time.

- Keep the Vast deadline adjustment default at 60 minutes for every worker version instead of silently falling back to 30 for older guards. Legacy guard restrictions remain explicit when applying an adjustment.

- Move Vast host history/preferences and exclusions into dedicated views selected from the existing optimizer Settings sidebar. Place rental actions in the sidebar and use the PBGui theme for cloud controls.

- Review Vast issues #345, #350–353 and #361: tolerate an absent Settings rental button, bind manual Rent to the selected offer, rebalance transfer allowance through confirmed shorter deadlines, and isolate bounded optimizer-log polling from stop/collection. Clarify and test intentional automatic CPU allocation against Min CPU cores; verify pre-start market-cache staging and reject incomplete/expired metadata before worker launch.

- Replace Vast's two-upload-attempt cutoff with persistent 15-minute transient-error recovery, 15/30/60-second backoff, renewed allowance on transfer progress and visible retry status. Separate verified worker setup from upload recovery while retaining cancellation, permanent-error checks and the rental collection reserve.

- Show Vast machine rental history and Working evidence in offer searches; add reversible manual Working and Preferred marks. Preferred hosts are searched explicitly and ranked first within existing limits, with blocked hosts always excluded. Preserve machine identity during rental supervision for future history.

- Add persistent Vast GPU host exclusions by Machine ID: block from offers or rentals, manage/unblock in Settings, resolve legacy rental identities on demand, and enforce exclusions in previews and again at rental start without stopping existing rentals.

- Investigated stalled Vast job `728b4268649b40c8975dd51b85fdda38`: the fetched host log reports all 27 worker-image layers waiting with none completed. Worker setup has not started, so its 15-minute timeout does not apply during image provisioning; no runtime behavior changed.

- Show unavailable rental-control reasons only on click, without persistent explanatory text in the cards.

- Preserve edited Vast budget, transfer reserve and deadline-minute inputs plus focus across automatic dashboard refreshes; discard drafts when switching rentals.

- Show manifest-size-weighted worker image progress in GB and percent for the pinned image. Completed/cached layers form an explicit lower bound, with extraction readiness shown separately; unknown images retain layer-count progress.

- Separate Vast Budget and Deadline cards; size amount fields for readable four-decimal transfer reserves. Review fixes cover upload retry logging, legacy rental compatibility, old-worker deadline steps, cleanup checks and guard restart persistence.

- Vast.ai uploads now retry transient SSH failures during remote input preparation and publication without consuming a full upload attempt. Rsync failures retain partial data and report a safe, actionable connection category.
- Make the Budget/deadline and transfer-reserve controls readable without clipped values or orphaned +/- buttons.

- Fixed Vast manual GPU rentals that could remain reserved after Start queue was pressed; queue start now releases the reservation idempotently and resumes supervision.
- Allow an active Vast rental's Budget target and transfer reserve to be edited from its top rental card; PBGui rebalances the acknowledged deadline and displays the transfer reserve used for input/results.

- Add a saved minimum-TFLOPS filter to Vast.ai GPU requirements, enforced for offer previews and final rental selection.

- Show Vast.ai local input preparation progress in the Queue, including copied MB, completed files and archive-compression state.

- Make Vast.ai **Save & Queue** return after the queue row is created; immutable OHLCV snapshot copying and compression now continue in the background before a rental can start.

- Allow Vast rental deadline controls to use a whole-minute adjustment entered beside the −/+ buttons, defaulting to 60 minutes.

- Display disabled sides as `-` in backtest result POS columns, including archive/legacy tables, when their position limit or total wallet exposure is zero.

- Reviewed the reported backtest POS value `4 / 5`: the column displays configured Long/Short position limits, not occupied/available positions. The inspected result has long n_positions=4 and short n_positions=5 with short exposure zero; no runtime behavior changed.
