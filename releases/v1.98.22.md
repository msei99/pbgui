# v1.98.22

## Improved

- PB8 Optimize now loads Configs immediately in parallel with settings/metadata and skips unused optimize-result inspection for the Configs table.

## Fixed

- V7 Run conversion now renders structured PB8 manual-review errors as a compact actionable field list instead of `[object Object]` or an oversized mapping report.
- Reviewable official V7 migration output now opens in the matching unsaved editor context: Run stays in PB8 Run, while Backtest Config and Result stay in PB8 Backtest. Nothing is published until explicitly saved.
- Migration review drafts now preserve their review report through shared editor normalization and reuse the existing V7 editor review status: bot sections and available structured fields are marked red, while fields without a dedicated control remain in the persistent review notice.
- V7 migration continues to pass the complete config to PB8 while filtering review prompts by editor context: Run excludes Backtest/Optimize findings and Backtest excludes Live/Optimize findings. Retired price-distance values now pass through PB8's canonical automatic churn-gate migration instead of appearing as manual-review fields, disabled retired volatility filters are dropped, and unresolved V7 paths are never inserted into the canonical V8 draft.
- Optimize migration reviews only evaluation-relevant Optimize, Backtest, and Bot findings while retaining the complete official migration report in the saved bundle; Run-only Live findings no longer block Optimize conversion.
- Optimize migration now removes PBGui-only metadata and the redundant legacy pending-evaluation default before invoking PB8, and genuine failures show compact actionable details instead of the full migration report.
- Repeating a V7 Backtest conversion whose V8 target already exists now opens the existing config directly instead of showing a redundant one-action dialog.
