# v2.04.7

## Fixed

- PB8 scenario backtests now align approved and ignored coin lists for an explicitly disabled trading side without enabling it. Existing queue entries are also corrected at launch. Conflicting lists with two active sides produce a clear validation error.
- Backtest runner exceptions and nonzero exits now appear in the job log instead of leaving only an error badge. Exception details remain available in the durable queue state.
- Refresh public exchange market metadata on PBGui before cloud startup for older queued bundles. Fetch and transfer authoritative first-candle metadata for the exported markets, preventing worker-region exchange restrictions from breaking startup. Preserve minimum coin age and reject incomplete metadata.
- Vast provider log requests no longer invalidate cached instance listings. Valid cached listings remain available during rate-limit cooldowns without extra API calls; fresh requests continue to honor Retry-After.
- Requeue immediately shows Preparing and disables repeated submissions, including while queue-table updates are deferred.

## Improved

- Synchronize Vast input files directly with resumable rsync over strictly authenticated SSH. Reuse completed content-addressed files across jobs, keep partial files separate, and publish inputs without a full remote cache scan or archive rebuild. Persist synchronization progress and reuse statistics, with cancellation and bounded retries.
- Retain the verified-chunk fallback for workers without rsync, including paged cache progress. Add rsync to PBGui installers and the worker image.
- Pin the published `ee2b7d4-queue-v3` worker image for new rentals. Older queue-v1/v2 rentals remain supported for recovery and cleanup.
- Show image-preparation activity, elapsed time, the provider log source and its actual snapshot age. Repeated polling no longer makes unchanged output appear fresh.
- Update English and German guides for backtest suite coin lists, synchronization and cloud metadata preparation.
