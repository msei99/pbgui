# v2.02.11

## Bitget UTA

- Added fail-closed Classic/UTA detection and native USDT perpetual wallet, position, paginated order, financial-record income and execution reads. Unknown or transitional account modes no longer silently select Classic.
- Normalize realized PnL, signed fees/rebates, funding payments and actual UTA execution sides. Explicit empty native lists are handled without accepting missing fields, failed responses or inconsistent pagination.
- Keep UTA and Funding balances separate, including a fixed Funding-assets GET fallback for the pinned CCXT version. Capital transfers are excluded from futures income.
- Serialize shared Bitget REST clients so simultaneous reads and credential replacement cannot corrupt routing or close a client in use.
- Bitget chart positions and orders use full REST snapshots approximately every five seconds in this initial rollout, for both Classic and UTA. Public candle streams are unchanged.
- UTA Market Close remains disabled with a clear explanation; verified Classic closing and existing transfer submission safeguards are preserved.

## Data Integrity

- Commit complete income batches and their scan-start checkpoints in one transaction. Failed persistence rolls back both so the next scan can retry safely.
- Preserve stored Classic history and prevent the Classic execution-side repair from inverting UTA order sides. Repeated UTA imports use stable, account-scoped income IDs.

## Maintenance And Documentation

- Removed the unused Python 3.10 requirements file and obsolete dependency fallbacks. Active Python 3.12 package versions are unchanged.
- Corrected stale support claims in the README, agent instructions and EN/DE guides: PBGui supports PB7/PB8 only. Historical release notes and migration safeguards remain intact.
- Added UTA permission guidance and documented the staged acceptance/migration plan. API-key management write access is broader than monitoring and must not be confused with a withdrawal scope.
- Thanks to @alexch03 for the original proposal and validation in [PR #129](https://github.com/msei99/pbgui/pull/129). This release provides a reworked implementation on current main rather than merging the original patch unchanged.

## Validation And Limitations

- Complete offline test suite: 8,035 passed, 41 skipped; 21 dependency/deprecation warnings.
- Authorized account checks covered empty and funded UTA/Funding wallets, transfer exclusion from income, and leverage readback. A single passive Post-only order using the inspected PB7 parameter builder and CCXT 4.5.48 was accepted and canceled without fills; post-cancel PBGui readback and unchanged balances were confirmed.
- Actual fill/fee/funding accounting has offline coverage but was not validated with real fills. Full PB7 startup, sustained UTA trading, recovery behavior and production-account migration are not certified by this release. PB7/PB8 bot code is unchanged.
- UTA history is limited to the provider's retained 90 days, queried in windows of at most 30 days. V3 does not reconstruct pre-migration Classic history. Unsupported or ambiguous ledger types and non-USDT fees fail explicitly rather than producing estimated income.
- No bot/VPS host was deployed, updated or restarted during release preparation. No production account was migrated. The release does not authorize those operations.
- API serial is incremented. After installing the update, ensure the API and any independent PBData process are reloaded to use the new exchange code.
