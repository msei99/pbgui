# v2.12.5

## PB9 Run host selection and remote logs

- Fix PB9 Cluster materialization incorrectly reporting an installed checkout as
  missing. The readiness check passed an unsupported `fallback` keyword to the
  INI snapshot reader and interpreted the resulting exception as a missing path.
- Keep an enabled remote instance's log viewer on its saved execution host when
  remote output is empty or temporarily unavailable. Old local output no longer
  replaces that host. Disabled instances retain local and backup log access.
- Keep previously detected but temporarily blocked PB9 targets visible in the
  shared Run editor, with their readiness reason. Preserve the selected target
  and unsaved edits while eligibility updates automatically. A missing or
  negative placement confirmation keeps the target disabled.
- Recheck request ownership after asynchronous capability updates and cancel
  outstanding capability requests when leaving the page. Existing PB8 behavior
  and server-side Cluster activation checks remain in place.

## Validation and rollout

All 264 focused offline release tests passed. These checks cover PB9 bundle transactions, the real INI snapshot
contract, remote log success/empty/error cases, PB8 and Cluster regressions, and
the shared editor in an isolated native browser. Fable reviewed the changes;
its concurrency and missing-eligibility findings were addressed.

Update PBGui on the controlling master and the affected PB9 execution host to
load the corrected API and Cluster code. This release does not change the bot's
saved assignment or move a running instance automatically. No VPS was updated,
no service was restarted and no trading process was started or stopped while
preparing the release.
