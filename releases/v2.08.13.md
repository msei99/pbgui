# v2.08.13

## Fixes

- Fixed #410: Concurrent first access to a new Market Data inventory cache could fail immediately with `database is locked` (SQLITE_BUSY during the WAL switch; reproduced in 35 of 100 multi-process cold-start trials). Cache setup (WAL switch and schema) now runs only when the schema is missing or the database is not yet in WAL mode, serialized across threads and processes by an owner-only lock file with a bounded 10 s wait. Normal connections only read whether setup is complete, so they no longer run DDL or WAL switches. A forked process gets fresh setup locks. Existing databases get an automatic WAL attempt per process instead of one per connection; if WAL is unavailable the cache keeps working in rollback mode and logs a warning, normally once per process. A deleted cache database is set up again on its next access, a connection is now closed when its setup fails, and the ineffective setup commit was removed.

- Vast.ai: Display missing or non-finite metrics as `Unknown` instead of `NaN` or `Infinity`, including the GPU recommendation's candidates/s rate (#426).

## Known limitations

- One earlier isolated multi-process cold-start failure could not be reproduced with phase diagnostics; its cause remains unknown. The confirmed simultaneous WAL-switch failure is covered by serialized setup.
- The NaN-related TypeError reported in #426 was not reproduced. This release corrects missing and non-finite metric display; it does not claim to fix an independently verified rendering crash.

## Validation

- 59 focused inventory-cache, PB8 inventory, Vast formatter/UI logic, help coverage and release tests passed; one Chromium browser test was deselected because browser launch is blocked in this sandbox.
- JavaScript syntax and whitespace checks passed. Graph change analysis reported low risk and no affected execution flows.
- A broader optional Market Data run was interrupted at the status event-loop responsiveness test, which also stalled when run alone; that test is not counted as passed.
- API serial 3248 exposes the restart requirement. No remote bot actions or production rental operations were performed.
