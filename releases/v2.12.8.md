# v2.12.8

- Prevent monitor/API restarts from creating false SSH outage/recovery alarms
  while initial connections are re-established. Give each startup host one
  bounded 60-second reconnect interval without delaying startup or hiding its
  live connection status. End the interval on first success, report persistent
  failures after expiry and authentication failures immediately, and preserve
  existing alert episodes until actual recovery. Normal later link failures and
  other hosts' service/system alerts remain active.

- Fix unchanged PB8/PB9 updates failing after a skipped interpreter check.
  Evaluate the unchanged-runtime guard before dependent registered result fields
  throughout local and remote update tasks; retain staging cleanup and the next
  imported runtime play. Cover the complete no-op task sequence with real Ansible
  conditions and harmless fixture actions.

- Compare prepared PB7/PB8/PB9 wheel contents with the installed runtime before
  replacement, across local and remote standalone/combined updates. Matching
  healthy runtimes skip dependency installation, checkout and bot/PBRun restarts;
  missing receipts or an inactive PBRun do not force reinstall identical wheels.
  Dependency-only repairs retain matching bot wheels, while changed/missing
  artifacts still install and validate normally. Preserve staging cleanup and
  subsequent runtime plays when one generation is already current.

- Restore intermediate deployment progress for imported PB7/PB8/PB9 playbooks
  and nested wheel tasks. Resolve display labels without executing templates,
  preserve repeated task positions, avoid early handler jumps, and reserve
  100% for a terminal outcome instead of treating a wrapper as an empty plan.

- Include PB9 in the VPS Overview's Passivbot and combined PBGui/runtime bulk
  updates. Use fresh per-host installed-generation flags and the existing
  guarded installers, preserving PB7/PB8-only routing, rollout mode, host locks,
  credential synchronization and deferred API restart. Never infer a new PB9
  installation or install PB7/PB8 on a PB9-only host from its legacy saved profile.

- Publish and pin the PB8 Vast worker for official revision
  `15d6404f`, retaining the published CUDA dependencies, worker protocol,
  rolling CPU HSL history and adaptive GPU memory/cache overlays. The official
  source now contains the EMA span-alias and fresh-population fixes. Bind the
  build inputs and source hashes, reject unreviewed overlay targets, and verify
  the native extension and checkpoint sampling offline. Update the job,
  validation and calibration pins together; preserve historical rental
  revisions and calibration evidence. The image is anonymously readable.
  Running rentals, PBRun and installed bot sources remain unchanged; no paid
  GPU test is included.

- Show the authenticated API's actionable metadata error in the shared Run
  editor instead of hiding it behind a generic HTTP status. An outdated PB9
  installation now explains that a runtime update is required; JSON errors
  remain plain text, and malformed error bodies retain the HTTP fallback.
- Add PB9 to the shared VPS Manager host-header cards and live updates. Separate
  installed artifacts from current risk-layout support through a bounded,
  non-executing source check in host telemetry; old or unverified layouts no
  longer look ready. Highlight the relevant Update PB9 action and send the
  Optimize runtime warning to the local-master update controls, preserving mounts
  ([#523](https://github.com/msei99/pbgui/issues/523)).

- Keep a single server-owned navigation restart request pending while protected
  operations or lifecycle locks are busy. Show the reason, resume automatically
  when safe, retain progress across browser reload and keep the idle fast path.
  Waiting does not expire the reconnect check or interrupt independent jobs.
- Retain completed restart-status inspections for three seconds instead of
  expiring slow scans before their results are published. Browser reconnect
  probes can reuse completed work; code/setting changes still invalidate it
  immediately, and action safety checks remain uncached.

- Support the current PB9 risk layout from Passivbot PR #2318 in Run, Backtest
  and Optimize. Keep the loss gate, optional drawdown cap and shared realized-loss
  memory in the native Portfolio controls. Reject retired PB9 development configs
  without migrating, rewriting or automatically deleting them; preserve result
  viewing and existing explicit-delete safeguards. Reject unsupported GPU risk
  policies through Passivbot's own preparation validator. Verify the official
  PB8-to-PB9 converter against the current layout for its three supported schemas.

- Detect outdated persistent VPSMonitor code through its startup serial, including
  reachable legacy daemons without serial reporting. Include stale local daemons
  in the Services API restart action as well as the navigation restart, so PB9
  log support is loaded without a separate manual monitor restart. Keep current
  monitors running and preserve all restart safety gates.
