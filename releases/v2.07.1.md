# v2.07.1 — Reliable API-key rotation and runtime fixes

## API-key rotation

- Verified exchange-key writes now create durable per-account credential revisions. PBRun gracefully restarts only the affected running PB7/PB8 instances after the new keys reach their host.
- Disabled bots stay stopped. Manual restarts are recognized, repeated synchronization does not trigger duplicate restarts, failed starts are retried, and failed stops cannot launch a second process.
- Cluster Sync node previews display credential adoption separately from file arrival, with automatic updates and no exposed secrets or fingerprints.
- The API Keys editor offers an optional shared Hyperliquid private-key update. Review every matching vault and main account, then confirm one atomic save. Other accounts keep their addresses and individual settings.
- Signed, short-lived previews reject concurrent changes. Recovery covers the complete account group, and stored expiry information is cleared for every affected account.

## Fixes

- #379: Missing PB7 imports and an unavailable PB8 Backtest runtime now produce actionable HTTP 503 configuration errors instead of generic HTTP 500 responses.
- #380: PB8 Strategy Explorer reports an unavailable runtime as HTTP 503 while retaining HTTP 422 for invalid requests.
- #382: Transfers render persisted history even when the exchange preview fails, preserve reconciliation access, and disable transfers using unavailable snapshots.
- #383: AI Chat avoids model requests for disconnected providers, prefers a connected provider on initial load, and retains its setup hint for new chats.
- #384: Single-job status reads use validated direct lookups under the queue transition lock instead of scanning up to 1,000 history files.
- #388: Coin Data progress polling is sequential, slows down in the background, and rejects stale responses after stopping or replacing a poll.

## Validation

- Full offline suite during development: 11,048 passed, 48 skipped, and 2 failures in outdated Coin Data polling and logging-policy test expectations. Both expectations were corrected; the subsequent focused regression run passed all 349 tests. The full suite was not repeated.
- The subsequent Hyperliquid shared-key addition passed 26 focused backend tests, including real writer/publication/revision integration, concurrent-change rejection, replay protection, save interruptions and publication failure.
- All 3 new isolated browser tests passed, covering the real menu entry, group preview, explicit confirmation, error recovery, automatic updates, navigation restoration and responsive sidebars. All 27 existing editor/config-sync regression tests passed after extending their single-account DOM fixtures.
- Related credential, expiry, TradFi, Cluster Sync, help and UI regression checks also passed. Tests used isolated data; no production key changes, exchange trades or remote service restarts were performed.

## Upgrade

Restart the PBGui API after updating, using the normal Restart control so active-operation blockers are respected. Reload open browser pages to use the updated editor and Cluster Sync preview.

Automatic credential adoption requires this PBGui version and an updated/restarted PBRun on each host running bots. Delivery and restarts happen separately on each VPS after verified key arrival; they are not simultaneous across hosts. Updating or restarting remote hosts is a separate deployment step.
