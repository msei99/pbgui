# v2.08.3

AI Loop Optimizer and its AI-assisted setup remain **experimental**.

### Changed

- AI chat now sequences clarification before review: unanswered quick replies block proposal tools across providers; a new clarification revokes pending approvals and replaces earlier unanswered choices, preventing simultaneous question and review requests.
- AI tool failures now identify the failed tool and safe validation reason in the activity history and PBGui.log, and explicitly distinguish a recoverable tool rejection from a stopped AI turn. Native PB8 validation errors are no longer reduced to a generic capability failure.
- Fixed #401: PB7 Optimize reads legacy limit statistics and modern suite reducer metadata without an AttributeError, and uses the installed limit basis field.
- Fixed #390 and #398: PB7/PB8 Optimize WebSockets share bounded queue scans, push only changed state and back off while idle. PB7 process recovery scans and unchanged log tails are cached; blocking scans run outside the event loop and unchanged reads no longer trigger notification storms. Hidden optimizer tabs defer rendering and results requests; visible active Results/Pareto views keep updating independently of queue changes.
- Fixed #385: Navigation alert polling pauses in background tabs, prevents overlapping requests, rejects stale responses and resumes immediately on return.
- Fixed #389: PB8 queue status reuses one queue snapshot, and workload estimates use a bounded, thread-safe file-identity cache while retaining containment and symlink checks.
- Fixed #393: Services status polling scans daemon processes once per request instead of once per stopped service and resumes pending credential mutations at most once per minute after success, also across concurrent requests. Polling stops as soon as the tab is hidden, refreshes immediately on return and never overlaps requests; refreshes requested by service actions are queued rather than dropped.
- Fixed #397: Dashboard live balance no longer fetches open orders or tickers it discards, and Hyperliquid balance reads its account state once. Live balance and positions widgets stop polling exchanges in background tabs.
- Fixed #386: Dashboard live positions share complete account-wide order snapshots across positions for Hyperliquid, Bitget UTA, Bybit, OKX, Binance USD-M and Bitget Classic. Native cursor pagination retrieves later-page DCA/TP orders; Classic Bitget explicitly includes partially filled orders, and active USDT/USDC settlements are retained. Invalid pages, cursor loops and failed reads discard the snapshot and use the existing per-symbol fallback. Database sync and action reads retain their existing per-symbol behavior; DB fallback loads orders and prices once per user. Verified with 435 focused offline tests using real CCXT parsers and simulated native pages. Binance's all-symbol endpoint has higher request weight, managed by the existing CCXT rate limiter.
- Fixed #399: PB7 Optimize status polls no longer sleep for CPU sampling, reparse the log excerpt and config only after the files change (failed reads are retried, not cached), and reuse the shared queue snapshot instead of two full disk and process scans per request.
- Review validation: Follow-up fixes for #386, #393 and #399 passed 54 focused tests and an additional isolated Chromium test covering polling cancellation in hidden tabs and immediate refresh after short and long tab absences.

- AI optimizer save proposals now accept separate scenario-generation parameters and preserve server-generated holdout provenance, fixing setup failures caused by rejected `pbgui.scenario_template` metadata. Training excludes holdouts; scenario changes are included in approval previews.
- AI chat: Added read-only candle inventory tools for actual local date boundaries, coverage and gaps across Market Data and PB8 caches, so training/holdout setup can inspect available data instead of asking users to supply known dates.
- AI chat instructions: Removed the special clarification example distinguishing requested Loop counts from optimizer-attempt limits; retained the general clarification rule for genuinely ambiguous requirements.
- AI drawer: Show activity and streamed ChatGPT assistant text inline in chronological order immediately after the latest user request, then collapse activity on completion. Removed the separate activity panel and duplicate footer. Added a header context usage ring using ChatGPT runtime token telemetry, with explicit unavailable state for providers without reported usage.
- AI chat: PB8 patch proposals and approval conflict checks now use the same in-memory legacy HSL migration as the config editor, preventing proposals from failing when rereading an unmigrated saved source. Original configs remain unchanged until approval.
- AI chat: Follow-up answers preserve pending AI Loop/Vast.ai configuration approval cards. Current pending proposal state is exposed to the model; explicit rejection, chat deletion and rewind still invalidate approvals.
- AI drawer: Show a visible working indicator and elapsed processing timer while a response is active; stop the indicator when processing finishes, fails or is cancelled.
- AI chat can now read, create and edit owned PB8 AI Loop definitions through reviewable save proposals, without relying on stale browser controls. Added typed Vast.ai preference reads and proposals for GPU requirements, rental count, budget, duration and automation, with shared-scope/cost disclosure, stale-write checks and idempotent approval recovery.
- AI chat setup guidance now explicitly requires clarification before replacing ambiguous requirements with different settings, and distinguishes missing tools or stale browser context from unclear user instructions.
- AI drawer: Resize the message input by dragging its top edge, with keyboard support, viewport bounds and browser-local height persistence; unfinished text is preserved while resizing.

- AI chat: Added scoped read-only tools to list current/historical bot logs across discovered VPS hosts and local runtime and retrieve real server-side log evidence, including whole-file literal searches, redaction, returned timestamps and explicit coverage/truncation limits. Bot diagnosis instructions now distinguish visible excerpts/current blockers from established historical causes.

- AI drawer: Keep approval continuations below the previous assistant answer instead of inserting their activity and streamed text above it; collapsed activity remains immediately before the new final response.

- AI Loops: Normalize Suite coin lists for disabled Long/Short directions without changing their risk or bounds; reject asymmetric universes with both directions active before launch. Failed cloud optimizer executions now retain their exit code and report Suite coin-list failures instead of mislabeling missing results as import errors.

- AI chat: Page actions wait for browser completion and return the updated page context, fixing Loop queue/start requests that continued with stale Config controls after navigation. Unconfirmed actions are explicitly distinguished from completed actions.

- Service restart: Handle code-version changes during an in-progress restart with one bounded follow-up restart after the replacement API is available. Show remaining outdated services and serial mismatches in progress and timeout messages; do not blindly retry same-version failures.

- AI chat: Restore saved drawer width before persisting open state, serialize preference writes and preserve preferred width when viewport-clamped. Confirm AI top-navigation actions on the destination page and allow 45 seconds for browser completion. Increase bounded provider tool budgets to 12 reading/40 action rounds and 128 calls; ChatGPT navigation failures remain distinct from tool-budget exhaustion.

- AI Loops Config: Use the shared red danger styling for Delete Selected, matching the Queue and Results deletion controls.

- AI navigation: Keep section/menu control identities stable across background config-list and badge-count updates; preserve resource-sensitive identities for configuration and action controls. Fixes Loop setup stopping after a new definition changes the sidebar count.

- Experimental AI Loops: Add native owner-scoped run-state reads and reviewed queue/start backend tools. Reuse native resource/model/rental validation, freeze reviewed selection and rental limits, reject stale definitions/runs, and detect already-created queue entries on execution replay. Loop queue/start no longer depends on browser navigation or table selections.

### AI Loop reliability and GPU worker

- AI Loop setup and autonomous decisions expose the pinned GPU worker's supported and exact-only metrics. Unsupported GPU scoring/limits are rejected before launch and after optimizer edits, with explicit alternatives; independent CPU comparison goals remain available.
- Fixed Long-only/Short-only Suite queue/start validation after coin normalization while preserving zero capacity on the disabled side and rejecting foreign coins or direction changes.
- Fixed generated Walk Forward/Sweep templates losing their protected Holdout windows. Both supported scenario-template contracts now retain Holdouts in queued Loops and result metadata, and validate the actual training suite before separating evaluation windows.
- Private GPU/Vast optimizer copies restore the previous `0.99` completion floor when the source requires exactly `1.0`, avoiding numerical boundary disagreements. Saved configs, drawdown limits, GPU agreement safeguards and independent exact comparison completeness checks remain unchanged.
- Failed optimizer jobs preserve their native stop reason; usable partial exact candidates can continue through selection and fixed comparison backtests.
- AI diagnosis can read recorded termination details, operation errors and owned optimizer/backtest logs directly, with redaction, bounded pagination and filesystem containment checks.
- Published and pinned a temporary worker backport for [Passivbot PR #1871](https://github.com/enarjord/passivbot/pull/1871): non-finite GPU suite candidate metrics receive the CPU optimizer's invalid-candidate penalty instead of terminating the whole batch. New rentals use the patched image; previous rentals and calibration evidence remain recognized.

### Validation

- Full offline run: 12,173 passed and 57 skipped. The 30 failures were caused by three outdated test fixtures (AI capability signature, navigation browser APIs/cache versions, and Help cache version); after correcting those fixtures, all 32 focused cases in the affected areas passed. The full suite was not repeated.
- Temporary GPU worker backport: 895 focused upstream tests passed with 6 skipped; five synthetic regression tests passed inside the read-only, network-disabled worker. Its immutable image and unchanged GPU metric contract were verified. No real CUDA performance test was performed.
- No live bot, VPS or paid GPU rental was started during release verification.
