# v2.04.6

## Fixed

- Check missing Vast cache files in pages of 1,024 entries using the existing worker protocol. Large multi-coin manifests no longer exceed the SSH response limit before upload begins.

## Improved

- Upload up to two independent 2 MiB blocks concurrently, with aggregate verified/in-flight progress, bounded retries and deterministic cancellation. Reuse verified chunks and send duplicate content only once before validating the final archive.

## Fixed CPU allocation

- Cap automatic optimizer CPU workers at the smaller of measured container capacity and the immutable rented offer allocation. A host reporting 256 CPUs for a 21.3-core rental now uses 21 workers.

- Fetch the provider startup log for manually reserved GPUs before queue start and show it for waiting jobs until their own log is available.

- Show Start queue beside the rented GPU in the queue list and distinguish a paused reservation from a started queue waiting for input preparation.

- Detect interrupted cloud input preparation after its owning process exits and expose Requeue instead of leaving the job permanently preparing.

- Keep the newest requeue attempt visible when an earlier preparation failed; old attempts no longer make the source job reappear during preparation.

- Continue fetching provider startup logs while SSH/worker setup is pending, even after Vast reports the instance running.

- Audit cloud log entry points and show cache checking, transfer archive preparation, and input installation as distinct upload phases rather than an empty byte progress bar.

- Show estimated upload time remaining from measured throughput, with a clearly labelled host-network minimum before measurements are available; suppress estimates during reconnect, packaging and verification.

- Compare measured upload and advertised host download speed in Mbps, show percentage reached and measured/theoretical remaining time simultaneously; payload sizes stay in MB.
- Add acknowledged, restart-safe rental deadline requests in 30-minute steps, bounded by the original budget, collection margin and 24-hour limit. Old workers remain explicitly unsupported. New rentals use the published queue-v2 image pinned in this release; existing rentals retain their original worker.

- Explain repeated GPU proxy dispatch progress in Suite runs and why exact results arrive only after CPU validation.

- Clarify how to compare multicoin GPU profiles without confusing workload growth, kernel execution and host performance.

- Fix shared live-log follow after delayed wrapped-row height changes and pointer release outside the viewer. Closing the viewer releases its follow timer and temporary pointer listeners; deliberate history scrolling remains respected.

- Publish and pin worker image `ee2b7d4-queue-v2` with the acknowledged deadline protocol. The isolated image smoke test and unchanged GPU metric contract pass; anonymous public manifest access and SHA256 are verified. Keep the prior exact image digest allowlisted so existing rentals can still be recovered and ended after upgrading.

- Align browser regression checks with the current log-viewer cache version and preserve the GPU search filter when selecting a rental offer.
