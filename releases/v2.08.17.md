## Investigations

- Investigated remaining CPU after the PB8 live-history patch without changing live code or the published PR. A three-minute read-only sample showed approximately 30.2% combined bot CPU, 6.57% monitor-agent CPU including children, and roughly 9% reaped-child accounting across four independent SSH servers. Identified short-lived `cluster_sync_command.py` workers; isolated cold imports cost 175 ms CPU median, making RPC batching/dispatch imports a concrete candidate. Reproduced a separate strided NumPy timestamp-search defect in broad standardized candle reads: a synchronous contiguous-vector prototype reduced a covered-gap check from 2,411 to 187 ms with 500 identical randomized comparisons. HSL raw-source reads bypass that standardization path, so no current HSL CPU attribution is claimed. Documented priorities, smaller capture costs and measurement limits in `docs/investigations/2026-10-16-remaining-cpu-performance.md`.

- Published upstream PB8 PR [#1994](https://github.com/enarjord/passivbot/pull/1994), `Reduce repeated candle and HSL history processing`, from isolated branch `perf/live-history-gap-cache` at `fb8bf8c644df4d4901ac41f736b1957491393817`. The seven-file change contains both performance fixes, synthetic parity/invalidation tests and generic PB8 contracts/changelog. Complete pre-commit graph analysis mapped 109 symbols and 22 affected flows without partial/truncated results. The PR excludes private VPS logs, account/configuration data and operator reports. Existing worker changes and the deployed trial were not modified by publication.

- Investigated the latest AI Loop timing increase: median optimizer time rose from 14.74 to 37.76 minutes while post-optimizer validation/AI time remained about 3.5 minutes. From the second recent round, AI retained automatically chosen validation/drift settings but left population automatic; PBGui's all-default auto-profile condition then stopped selecting population 8192, causing PB8 to use 1024. With 64 exact validations per generation and the same 100,000-proxy quota, exact work increased from about 800 to 6,100 candidates. This configuration handoff explains the major runtime increase; no optimizer, rental or runtime settings were changed by this investigation.
