# v2.05.2

- Documented a deferred PBGui-owned Vast GPU population calibration design that can benchmark retained rentals and reuse verified workload-specific profiles without adding autotuning code to PB8; current runtime behavior is unchanged.
- Recognize current upstream PB8 `GPU temporal replay` progress in local and Vast.ai optimizer status, including suite pass, scenario, history fraction, processed bars and estimated remaining time, while retaining compatibility with older PB8 progress messages.
- Published and pinned a production Vast worker with the minimal disabled-HSL CUDA kernel specialization, removed its temporary A/B runtime switch, and verified bit-identical full-state and specialized kernel outputs on an RTX 3090; the worker retains the verified content-addressed upload cache.
- Fixed stopped external Vast optimizers remaining visible as live 100%-GPU runs after observer loss, fixed a requested stop before the first exact result being mislabeled as a failed result import when its verified native result file is empty, and clear stale local-supervisor errors once the GPU-pool service is running again; API startup also repairs already persisted false failures automatically.
- Idle Vast GPU workers now detect a single PB8 optimizer already running inside their owned container, mirror its bounded log and progress into the GPU card, and expose its own read-only detail dashboard and shared log viewer without claiming lifecycle ownership of an unrelated process.
- Fixed retained-worker optimizer detection when PB8 receives `optimize.json` as a path relative to the optimizer process's working directory.
- Requeued Vast jobs now reference a previously verified immutable remote OHLCV tree when its complete file manifest matches, replacing another 120,000-file hard-link publication and cache scan with a constant-size snapshot link while retaining job-owned configuration and results.
- Added selectable Vast GPU idle retention and made **Keep until rental deadline** the default, with immediate, 5-minute, 30-minute and 1-hour cleanup alternatives plus the active policy on idle GPU cards, so uploaded multi-gigabyte inputs and worker caches survive follow-up tests.
- Added live GPU board power and power-limit readings below the utilization percentage in Vast optimizer details, making a misleading 100% busy reading easier to assess against the card's actual wattage.
- Reused verified market shards through metadata-preserving hard links across sequential optimizer jobs on the same Vast rental, avoiding duplicate multi-gigabyte transfers while keeping each job's configuration and results isolated.
- Fixed a reused Vast input snapshot retaining its predecessor's job-specific OHLCV path, which made a fully uploaded Requeue fail immediately with “No coin data found”; every execution copy now binds the immutable data to its own remote job directory and repairs stale cached execution metadata before upload.
- Fixed terminal Vast optimizer details showing the current rental's live activity after that job had already failed, completed, or been cancelled; the activity field now identifies the selected job's terminal state and timestamp while the concrete failure remains in Last error.
- Added coordinated rental-aware PB8 CUDA tuning: with automatic sizing enabled, cards up to 8 GB use 2,048 proxy candidates, cards below 11.5 GB use 4,096, general cards from 11.5 GB use 8,192, balanced fast 16 GB cards use 16,384, and measured high-throughput cards from 20 GB use 24,576; Exact validations, drift probes, drift window and dispatch envelope scale with the selected profile so GPU throughput no longer dilutes Exact evidence. Wider profiles require matching VRAM, memory bandwidth and compute data, so capacity alone never promotes an unknown card.
- Kept automatic CUDA candidate dispatches as wide as their coordinated hardware profile so PB8 launches enough 32-thread blocks to occupy the rented GPU's SMs; progress timing is no longer allowed to narrow candidate parallelism and produce a misleading 100%-busy reading at low board power.
- Expanded the automatic 12 GB CUDA profile to 8,192 candidates after a live 41-coin RTX 3060 run showed that 4,096 candidates left too few resident blocks for the card's 28 SMs; coordinated Exact and drift evidence scales with the wider generation.
- Kept Vast optimizer observation compatible with unmodified PB8 workers: before the first native progress message, PBGui still attaches to the process and log and shows a neutral running state instead of treating missing telemetry as a failure.
- PBGui now resolves and writes the complete hardware-aware CUDA profile for every Vast execution, including coordinated population, Exact-evidence and dispatch settings selected from usable VRAM and verified throughput classes; these are standard PB8 GPU options and do not require worker-side automatic selection.
- Performance History now retains the applied automatic GPU profile with each run so future recommendations can compare matched workloads and hardware without inferring settings from mutable source configs.
- Fixed Vast.ai Requeue leaving an authorized Auto rent & start GPU pool paused after a failed optimizer attempt.
- Made the paused GPU-pool state prominent in Queue and added a direct **Resume auto start** action for waiting jobs.
- Fixed large Vast.ai input manifests failing before rsync when many dated market-data shards made the manifest exceed the control-record size limit; the separately bounded manifest/worker metadata path now supports up to 1 GiB for broad 500+ coin runs while mutable control records remain capped at 16 MB.
- Added live input-archive compression progress with processed bytes, percentage, measured throughput and estimated remaining time.
- Fixed a missing Vast provider log remaining on its initial waiting placeholder after PBGui had already verified the worker connection.
- Fixed Vast worker provisioning requesting the image-pull log after the container was already running, which could overwrite the provider result used to pin the SSH host key and stall a ready rental before upload.
- Fixed the first upload attempt after SSH verification failing with an internal unbound provisioning-log helper when the container had already reached `running`; the same controller now advances directly to upload on its first pass.
- Vast worker controllers now retain a local traceback for unexpected controller failures while continuing to expose only the existing safe diagnostic in the UI.
- Fixed the persistent Vast GPU-pool scheduler keeping imported rental code after an API restart: it now reports its startup serial, appears in the shared Restart action when stale, and reloads without ending existing rentals, uploads, or optimizer jobs.
- Fixed newly created Vast instances getting stuck in provisioning after Vast retired its v0 instance-list endpoint: PBGui now follows every page of the official v1 listing, preserves the shared bounded cache, and no longer mislabels an instance-list HTTP 410 as an unavailable offer.
- Fixed a cancelled Requeue attempt hiding its still-running predecessor from the Queue API, which made an active GPU card incorrectly display “No active optimizer” and opened the cancelled attempt in the detail panel.
- Fixed an open shared log viewer remaining disconnected and empty after a PBGui API restart; active panels now reconnect automatically without repeatedly replacing healthy WebSockets.
- Requeue after a provider-side Vast.ai startup failure now references an unchanged, verified input snapshot and hard-links its single compressed archive when config, job parameters, PB8 revision, and worker image still match; retrying a 100,000-file job no longer walks every market shard or copies and rehashes multiple gigabytes before it can return to the retained GPU.
- Reused snapshots preserve the prepared optimizer config byte-for-byte so its manifest digest remains valid before hardware-specific tuning.
- A temporary local PB8 install/update lock during post-upload config preparation now enters the resumable upload retry window instead of failing the cloud job and abandoning already transferred data.
- Keep a worker-owned Vast.ai optimizer visible in the queue and GPU card even if stale local deletion metadata exists, so PBGui can reattach its log and progress instead of claiming that no optimizer is active.
- Vast direct-input synchronization now labels its live counter as GPU-cache comparison and reports final reused bytes separately from actual rsync network bytes, so a warm 2.4 GB cache no longer looks like a repeated 2.4 GB upload.
- Warm Vast workers now verify their complete content-addressed input cache before PBGui constructs rsync's temporary sender tree, so an unchanged 100,000-file Requeue skips both network transfer and another large local hard-link pass.
