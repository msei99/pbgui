# v2.06

- Keep GPU calibration input synchronization on rsync while treating its
  unclassified SSH/rsync exit 255 as a transient failure, allowing the existing
  bounded, resumable upload retries instead of failing the paid test immediately.
- Count Vast result-snapshot bytes only after size and checksum verification;
  discard failed temporary downloads without replacing the prior snapshot.
- Restart the single Vast jobs polling timer after manual actions so they do
  not trigger an additional near-immediate `/jobs` request.

- Published and pinned calibration worker v3 (`69227b7-calibration-v3`), adding
  live population progress and PCI/compute hardware identity on the same PB8
  revision and heartbeat base. The previous worker images remain supported for
  existing rentals and completed evidence.
- Show Vast's advertised GPU power limit beside each pre-rental offer, with an
  explicit fallback when the provider does not report it; live GPU telemetry
  remains the verification of the configured limit after rental.
- Show completed GPU calibration evidence and its acceptance action in GPU &
  Offers only for the selected offer's advertised GPU name and VRAM; prevent
  stale selections from accepting a different card's pending profile.
- Published and pinned the protocol-v2 calibration worker (`69227b7-calibration-v2`).
  New performance tests are enabled again; completed v1 profiles remain usable
  across this wrapper-only update with the unchanged PB8 revision and kernels.

- Added isolated Vast PB8 GPU performance tests beside Rent. Tests freeze
  PBGui's fixed versioned BTC/ETH/SOL 2024 comparison workload before rental,
  use the published worker's 300-second optimizer heartbeat to bound each case,
  and after the 1k–8k anchors probe every 4k step while throughput gains at
  least 10%, without the former 32k ceiling. VRAM reserve, rental deadline and
  a 131k safety limit bound large-card tests and record why probing stopped. Results
  distinguish exact runtime GPU/VRAM variants (including mod cards), remain
  pending until explicitly accepted, and can be repeated. Accepted local
  profiles override matching bundled PBGui references without changing them;
  otherwise the existing hardware heuristic remains the fallback. Canonical
  input preparation starts only after confirmation, reports Queue progress and
  rechecks the offer before any rental. Disabled actions now state their reason
  prominently, while an idle automatic pool is paused by an explicitly
  confirmed manual rental or calibration instead of blocking it. The canonical
  three-coin GPU workload pins both `n_positions` search ranges to PB8's valid
  `[1, 3]` multicoin foundation range before any rental. The new immutable
  calibration worker extends the heartbeat image with the bounded adaptive
  runner and is pinned by its anonymously verified manifest digest.
- Kept completed GPU calibration case rates and recommendations visible in
  Queue and GPU & Offers, cleared stale preparation text, and allowed an
  existing pending result to be accepted after reload. Accepted evidence now
  applies to the exact runtime GPU variant across later workloads on the
  matching PB8 and worker revision instead of being limited to the canonical
  comparison workload. Fixed result-duration formatting so rendering a
  completed test no longer interrupts GPU offer search initialization. A
  provider-rejected rental that never created an instance is now reported as
  such, including for already saved jobs, instead of as a disappeared GPU.
- Streamed each active GPU calibration population into the visible optimizer
  log instead of publishing it only after that population ended. Atomic local
  log replacements now append only genuinely new lines, preventing duplicate
  content and the visible top-to-bottom scroll jump during automatic updates.

- GPU calibration profiles now include the measured power limit. Real rentals first use an exact profile, then the closest power-limit profile only within the same runtime GPU name, VRAM, PCI device and compute capability; modified-VRAM cards stay isolated. The initial nvidia-smi sample is collected before execution settings are frozen, and Queue shows whether the selected profile was exact or nearest. Existing 3060/3090 results reuse their saved 170 W/200 W telemetry without rerunning. Completed tests can be repeated; the offers UI now displays the exact reason whenever a performance test is temporarily disabled.

- Vast optimizer startup now stages fresh local PBGui market snapshots and matching local PB8 first-candle caches instead of requesting exchange metadata during a paid GPU rental. Queue rental checks cache freshness and exported symbol coverage before creating a paid worker.
- GPU calibration and runtime profile matching use only the power limit sampled from the rented worker via `nvidia-smi`; the Vast-advertised cap remains offer metadata. Tests without a valid measured limit cannot become reusable profiles, and jobs without live measurement will fall back to the existing GPU heuristic rather than an unverified exact match.
- Removed trailing whitespace from Vast market-cache regression coverage.
