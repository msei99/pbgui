# v2.02.13

## Fixed

- Release a Log Viewer panel's socket, pending work, retained line/filter buffers, VPS state, and rendered rows when the panel closes. API Keys now also performs this cleanup on in-page Back navigation and page exit, while reopening retains the selected Lines setting and fetches a fresh snapshot.
- Stop multi-megabyte VPS monitoring state snapshots from reaching the local-only API Keys log viewer. Its authenticated `/ws/vps?state=0` connection now receives only explicit local file and log protocol messages, while remote-capable viewers retain initial and periodic state updates.
- Eliminate repeated API Keys page work from rescanning a 50,000-line browser model for every live log record. Local active filters now use bounded server-side literal/preset-term matching with exact source positions, context, sliding match counts, stale-response protection, compact live payloads, and complete-tail downloads; legacy and remote streams retain the optimized browser fallback.
- Search active-filter snapshots directly from the complete in-memory log model instead of first creating up to 50,000 unfiltered DOM rows. Keep collapsed results to block headers, materialize ordered details incrementally on expansion, retain exact match counts, line numbers, downloads, and streaming order, and keep expansion cancellable.
- Render collapsed log-search details lazily instead of rebuilding thousands of invisible highlights on every filter change. Avoid unchanged row-attribute writes and paint expanded details in small cancellable batches; add high-volume match/block coverage and sustained real-log keyboard/stream diagnostics.
- Add full API Keys page keyboard regression coverage for selecting large line counts with an active filter and typing during snapshot rendering and after filtering; include an explicit read-only local-log replay opt-in without logging message contents.
- Return the requested number of newest local log records even when lines exceed the previous 200-byte estimate; retain chronological order, bounded per-line tails, and the snapshot-to-live cursor handoff. Clarify collapsed API-key search blocks in the EN/DE guide.
- Display a successfully read empty Bitget UTA destination wallet as `0 USDT` instead of `Unavailable` in Profit Sweep.
- Reconcile accepted Bitget UTA transfers through the required `OTHER` capital ledger instead of leaving successful operations in `Unknown`.
- Show PB8 Cluster support from the actual PBCluster/hello capability handshake instead of marking nodes without persisted capability metadata as `Unsupported`.
- Open the API Keys log panel on the active grouped `PBGui.log` instead of the retired empty `ApiKeys.log` path, prefiltered to the exact `[ApiKeys]` tag.
- Keep large shared-log searches responsive by chunking filter preparation and avoiding per-line collapse writes.
- Bound long-line previews and highlight markup in the shared log viewer while retaining full loaded text for search/download; skip offscreen line layout, keep collapsed details hidden during filtering, cancel stale searches on clear/close/reload, and fix individual block collapse after Expand all and invalid-pattern handling.

## Validation And Limitations

- Complete offline test suite: 8,092 passed, 48 skipped.
- Focused Chromium interaction tests covered large filtered snapshots, incremental rendering, live log updates, cleanup, and stale-response handling; opt-in read-only replay diagnostics do not run in the default offline suite.
- The periodic multi-second Chrome freezes observed during validation were traced to the Avast SafePrice browser extension; disabling that extension removed the freezes.
- No PB7/PB8 bot code was changed, and no bot or VPS host was modified during development or release preparation.
