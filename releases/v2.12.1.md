# v2.12.1

## Fixes

- Fixed PBCoinData consumer detection on lean VPS installations: lifecycle
  inspection reads only authored PB7 demand metadata and no longer imports the
  native bot configuration pipeline. Invalid or incomplete input remains
  conservative/unknown. Normal bot configuration loading and saving retain the
  native pipeline.
- Fixed false Cluster manifest warnings for running instances: the monitor now
  excludes local `monitor.json` and `monitor_cache.json` telemetry files,
  matching Cluster/PBRun checks. Actual configuration and version mismatches
  remain blocked. Regression coverage includes PB7, PB8 and PB9.

## Validation

- Focused lifecycle, monitor, process ownership, Cluster state, PB7 configuration,
  PBCoinData and logging checks: **1,355 passed, 11 skipped**.
- The final expanded lifecycle/monitor regression files passed all **360 tests**,
  including a fresh Python process with NumPy, Portalocker and Dateutil blocked
  and a comparison against pinned native PB7 configuration defaults. Counts
  overlap and are not additive.
- Final release checks, including release metadata, help coverage and logging
  policy alongside those lifecycle/monitor regressions: **379 passed**.
- The five initial regression cases failed before their fixes.
- Fable found no blocker in its bounded read-only review. Its requested
  dependency-isolation and missing-metadata checks passed afterwards.
- The test-suite gate selected focused validation for this patch release; no
  complete offline suite was repeated.

Version **v2.12.1**, API serial **3798**. Existing experimental PB9 qualification
limits from v2.12.0 still apply. Publishing this release does not update remote
hosts or restart their services; the corrected code must be loaded through the
normal PBGui update workflow on affected hosts.
