# v2.08.4

### Changed

- Fixed #396: PB8 Backtest queue WebSockets share one bounded queue scan across clients, push only changed state and back off to 8 seconds while no job is running or waiting for autostart. Queue actions force an immediate fresh scan; hidden Backtest tabs pause server-side scanning until they are visible again.
- Fixed #400: PB8 Optimize reuses the terminal status of unchanged job logs instead of rereading their 64 KB tail on every queue evaluation. Autostart selection and the launch order recheck no longer load display rows or estimate candles and run outside the event loop. Stopping the controller, including concurrent stops from several tabs, waits for an in-flight autostart claim and releases a claim that completes late. Launches run in an owned executor and publish their process ownership or release their claim in the launch thread itself, even if the event loop closes. API shutdown joins outstanding launches before closing dependencies, without terminating detached optimizer jobs.
- Fixed #392: Vast.ai job polling parses a log tail only when the log changed or a lost throughput snapshot can be restored from it, and no longer reads stop requests of finished jobs. Polling backs off from 10 to 30 seconds while only finished jobs remain and no rental is active.
- Fixed #394: Concurrent Services worker status requests share one snapshot for 3 seconds; worker actions invalidate it, and scans started before an action can no longer repopulate it with stale state. Worker polling stops in hidden tabs, resumes immediately on return and polls the full worker status every 10 seconds.
- Fixed #387: VPS Manager reuses parsed host inventory files while they are unchanged. The push loop synchronizes the inventory once per tick instead of twice and still applies the stored host state on every tick, including while another refresh holds the refresh lock, and branch tracking remotes are read with one git call instead of one per branch.
