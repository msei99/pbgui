# v2.04

## Added

- Integrate Vast.ai GPU optimization into PB8 Optimize: configure credentials and GPU requirements in Queue Settings, validate configurations in the editor, and manage local and cloud jobs in the same queue.
- Run FIFO cloud jobs on a shared, supervised GPU rental with per-job inputs/results, persistent recovery, rental budget/deadline controls, idle cleanup, and verified deletion. Support explicit Start, Requeue, Pause, Resume supervision, End rental, and Stop & collect actions.
- Use a pinned public PB8 CUDA worker image with native Rust source identity and dependency licenses. Verify image availability before renting; normal public-image use requires no registry token.
- Prepare isolated config and data exports with verified HLCV datasets and fresh public market caches. Support PB8's 1–64 distinct-coin GPU scope and reuse verified data on the shared worker.
- Show rented GPU specifications, allocated CPU/RAM, memory/PCIe/disk bandwidth, network rates, rental and transfer prices, host reliability, and deadline in the job dashboard.
- Display provider-reported instance charges with billing-read permission, cached independently of job status. Show Pending until billing data is available.
- Show GPU/CPU utilization, RAM/VRAM use, elapsed time, Pareto count, outstanding CPU validations, and measurement age. Use measured container CPU allocation for new cloud jobs' validation workers.
- Add optional convergence stopping based on exact Pareto hypervolume, minimum evaluations, patience, and relative tolerance; show progress and explanatory hover help.
- Import verified intermediate result snapshots and final results into the same Optimize result entry. Refresh open Results/Paretos when snapshots arrive.
- Add direct Queue Backtest and Queue Validation actions in Pareto Explorer and Optimize Paretos without leaving the page, with explicit Open Queue navigation, queue count, autostart status, immediate feedback, and duplicate-click protection.
- Add Pareto Explorer validation for Holdout, Full timerange, both, or Training + Holdout + Full timerange. Preserve overrides and saved holdout periods, and group the resulting backtests.

## Changed

- Allow the complete PB8 GPU validator contract in Vast scoring and limits: 157 supported metric names and 460 accepted spellings including aliases. Verify the existing worker's metric sources against current PB8; CPU-only metrics remain excluded.
- Applying Sweep Cycles restores the three-objective scoring preset for EMA and Trailing, using ADG for Vast GPU, Sortino, and worst drawdown. All supported metrics remain available for manual changes.
- Persist Scenario Generator settings separately from applied scenario provenance and restore older saved templates instead of resetting to default windows.
- Keep cloud setup in the standard Optimize Queue Settings main view and runtime controls in the shared draggable/resizable log window. Use consistent queue actions, status badges, and validation selector sizing.
- Show a waiting message until the current job has its own provider or optimizer log. Display image-layer preparation and upload byte/percentage/speed progress, then switch to optimizer output and progress.
- Provide explicit validation correction actions without silently changing scoring or limits. Validate stepped/fixed bounds, strategy/profile support, scenarios, GPU sizing, and multi-coin limits before queueing.
- Add isolated offline and browser regression coverage and update the English and German guides. Include reproducible GPU benchmark, worker packaging, and offline-cache documentation.

## Fixed

- Refresh the shared log-viewer asset consistently across pages; update logging ownership audits and deterministic browser regression coverage for the new worker and log lifecycle.

- Prevent duplicate requeue replacements and transient duplicate rows; retain original jobs if preparation fails. Preserve immediate starting/stopping feedback across refreshes.
- Block new starts while rental cleanup is unresolved. Coordinate provider polling and rate-limit backoff across processes, and resolve ambiguous creation through fresh verified absence checks.
- Separate image loading from worker setup timeouts, reset setup time for new attempts on an existing rental, and retain the rental deadline during recovery.
- Verify SSH identity using rental-bound public-key records, run operations from the pinned PB8 checkout, and resume verified upload chunks after SSH disconnects instead of retransmitting the full archive.
- Handle transient provisioning-log availability, restricted download locations, and exact missing-container responses without presenting them as optimizer failures. Clear recovered warnings after successful worker verification.
- Keep log tail-following stable through filtering, long GPU profile messages, deferred layout, and window resizing while preserving intentional scrolling into history.
- Open Pareto Explorer correctly from same-origin Optimize result and log routes. Show selected configuration details beneath the Correlations radar.
- Remove container-only HLCV paths from local backtests of cloud results. Recover historical Explorer validation groups and invalidate cached summaries so existing results regroup without rerunning them.
- Preserve stable validation group and operation identifiers when partially completed queue submissions are retried.

## Compatibility notes

- New CPU-allocation and convergence settings apply to newly prepared runs; existing runs retain their execution configuration.
- Provider billing can be delayed and requires billing-read access. Resource readings and CPU backlog are sampled, not continuous measurements.
- Multi-coin GPU export is covered by source inspection and offline tests; paid multi-coin acceptance remains unverified.
