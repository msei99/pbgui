# v2.08.1 — PB8 8.6 compatibility and experimental AI Loops

## Experimental: PB8 AI Loop Optimizer

**The new AI Loop Optimizer is experimental.** This includes autonomous optimizer adjustments, saved learning, continuation, automatic evaluation and editable AI instructions. These features are still being validated and may change in later releases.

- Added named AI Loops Config, Queue and Results views. Create a Loop from an existing optimizer config, queue snapshot or result, then edit goals and use Save or Save & Queue.
- Run local CPU/GPU or Vast.ai optimizer experiments with fixed user goals, configurable per-run iteration/proxy/time limits, total run/time allowances and existing rental limits. Successful comparable exact backtests are required before adaptive continuation.
- Carry the best exact-comparison bot parameters into subsequent rounds only when they improve on the starting baseline. Ties and worse rounds keep the incumbent; AI-proposed optimizer settings, bounds, scoring and limits remain independent.
- Show per-round metrics, applied configuration changes, timing, optimizer logs and explicit termination details. Continue from the retained best or a chosen round with the current shared AI selection and an explicit additional-round count.
- Added bounded transient AI retries and progress-aware GPT timeouts. Managed API restarts wait for in-flight AI requests; completed jobs and durable controller state can be recovered without duplicating launches.
- Added AI Loops Knowledge in the sidebar for saved findings and their evidence. Added AI Instructions for viewing the built-in prompt, saving private immutable versions and selecting instructions for new runs. The default and saved versions are read-only; a unique new name unlocks an editable copy and enables Save. Personal versions can be deleted; deleting the active version selects PBGui default. Run details show the frozen prompt actually used; existing runs retain their snapshots, including after deletion.
- Run user-only Holdouts for complete comparison candidates and a Full Time Range for the best valid Holdout candidate. Compare all Holdouts or all Full Time Ranges from a selected run, or select Top X candidates in the comparison. Ranking uses target compliance first, then the evaluation score for the chosen period; selection updates automatically and survives browser reload. These user-evaluation results do not guide AI optimization, learning or continuation; final confirmation checks the unchanged AI-selected candidate separately.
- Preserve selections, filters, editor focus, unfinished Continue inputs and report navigation during automatic updates. Detail windows support dragging/resizing and restore their geometry and navigation.
- Experimental AI Loop comparisons now open the result list without automatically loading all curves. Choose All or Top X and click Apply comparison to start; browser reload preserves an explicitly started comparison.

## PB8 8.6 compatibility

- Added native configuration migration drafts across Run, Backtest and Optimize, including HSL changes, adaptive entry cooldowns and current optimizer options. Source configs remain unchanged until Save; unresolved HSL policies require an explicit selection.
- Show migration changes at the affected JSON paths and structured fields. Removed HSL values appear individually with their previous values instead of broadly highlighting unrelated sections.
- Fixed flattened Forager fixed-parameter selectors that prevented native initialization. Logs can open independently of config-editor validation, and local migration requirements no longer mislabel running VPS bots as config errors.
- Automatically migrate captured AI Loop inputs on Save and before creating a queued run, including Coin Overrides. Existing run history and source configurations are preserved.
- Updated HSL result charts to use native scope reports and controller transitions. Added a shared PB8 update warning with the config review/save workflow instead of repeated overview warnings.

## Vast.ai and optimizer execution

- Updated the pinned public worker to official PB8 revision `061e472e3d400cb3a740583d52f9d46e02eaf781` and schema v8.6.0, with the matching GPU metric contract and image-layer sizes. Existing rentals keep their recorded image; new rentals use the updated pin.
- Fixed current PB8 progress-counter parsing for proxy limits and Proxy/min, Exact/min, Proxy/Exact and estimated Exact/USD. Seed and pending work are excluded from completed evolution counters; sampled limits can still overshoot during native in-flight work and collection.
- Retain owned GPU workers between Loop optimization rounds, local validation and AI evaluation while respecting stop, pause, cleanup and rental deadlines. Local backtests use local CPU capacity instead of inheriting cloud-worker CPU counts.
- Validate GPU drift/probe/window combinations before allocating Loop jobs. Dataset guards now compare content so byte-identical candle rewrites do not invalidate an experiment, while changed inputs still block mixed-data comparisons.
- Added a custom rental idle timeout and preserved edited values during automatic updates.

## Other fixes

- Persist shared AI provider, profile, model, reasoning and speed per account across page changes and reloads. Update the bundled Codex CLI dependency to 0.159.2.
- Repair stale Dashboard Orders candles using authoritative snapshots, preserving newer live candles and the visible range. Derived price and unrealized-PnL displays update consistently; stale requests are discarded on timeframe changes or teardown.
- Improve shared top-navigation menu switching, report-window controls and navigation restoration. Updated English and German guides for all affected workflows.

## Upgrade

- Update dependencies and restart the PBGui API through its normal restart-required control.
- For a PB8 VPS schema upgrade, review and save affected configs so the migrated configs are delivered to the updated PB8. Alternatively, update an idle VPS first and move bots in stages. This release does not update or restart remote bot/VPS hosts automatically.
- New Vast.ai rentals use the new worker image after the PBGui API update; existing rentals are not rewritten.
