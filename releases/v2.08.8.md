# v2.08.8

## GPU optimization and PB8 compatibility

- Older PB8 Optimize configs now show native default additions, value changes and removed fields when opened, with orange field/Raw JSON markers, before/after tooltips and an expandable change list. Files remain unchanged until Save; unchanged configs show no adjustment notice.

- Fixed local GPU preflight failures caused by PB8 status output corrupting config-helper responses.
- Fixed Cloud exports rejected by older workers because disabled HSL budget-scaling fields were included. Incompatible prepared jobs now show a re-preparation message while compatible jobs can continue.
- Pool capacity, offer selection and rental-start/profile checks now use the same worker compatibility gate as dispatch. Older idle rentals cannot suppress a required compatible rental; mixed queues match jobs to usable existing workers regardless of queue order.
- Added per-side HSL budget scaling for Coin mode. Checkbox and Bot JSON edits stay synchronized, including corrections after switching HSL modes; saved legacy overrides are imported once when opening the editor.
- Preserved GPU Auto values separately from zero and fixed worker counts when loading, editing and saving configs. The CPU field shows its host limit, rejects oversized values instead of silently shortening them, and keeps CPU-backend decrement at one. Vast still derives its worker count from the rented CPU allocation.
- Removed the obsolete Raw/Bounded excess-allowance migration choice. Converted Backtest drafts display PB8's behavior-change warnings; the minimum-coin-age choice remains available.
- New Vast rentals use official PB8 `b9d6692ea` without the separate PR #1871 backport. Existing rentals retain their image and accept only compatible jobs. New-revision jobs use conservative hardware fallbacks until fresh calibration is available. GPU hardware and real checkpoint/resume acceptance are still pending.
- Updated the English and German Optimize and Backtest guides, including the V7-to-V8 conversion instructions: native excess-allowance warnings replace the retired Raw/Bounded choice; the minimum-coin-age choice remains.
