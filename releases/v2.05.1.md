# v2.05.1

## Maintenance
- Require release completion to include substantive resolution comments, closure, and final-state verification for issues fully fixed by the release, without a separate user reminder.

## Features
- Vast.ai: configurable GPU pool (default 1, up to 16 concurrent rentals) dispatches prepared jobs across separate GPUs, reuses idle workers, persists explicit pool authorization across API restarts, and counts provisioning/cleanup toward the cap. **Auto rent & start** makes Save & Queue sufficient after one explicit settings confirmation, including with a one-GPU limit. Pause prevents new dispatch/rental; End rentals disables automation and stops all leases. Per-job logs and budget/deadline controls target the correct rental. Per-rental and aggregate simultaneous budget targets are displayed; automatic replacements require pool consent. Pool authorization is bound to the configured Vast credential generation.
- Show each active GPU as a compact card above the optimize queue with its instance, job, phase, upload bytes/percentage/rate and saturation against advertised host bandwidth, exact/proxy progress and fresh proxy/min rate. Each card opens its detailed log and available optimizer result directly. Start and end actions target that GPU. With Auto rent & start enabled, confirmed **Replace GPU** waits for verified cleanup before restoring pool capacity and automatically returns unstarted input to the queue while preserving runs that already produced results.

## Fixes
- Require an explicit shared PBGui confirmation before stopping and collecting a running Vast.ai optimizer.
- Classify successfully collected automatic optimizer stops at convergence or the rental deadline as completed while preserving the completion reason; user-requested stops remain cancelled.
- Use the same Rsync progress source in compact GPU cards and the job log, so direct-file uploads no longer show 0% above while the detailed log is advancing.
- Keep **Save & Queue** clickable during background Vast.ai compatibility checks. The click now always enters the visible pending state and performs its own authoritative validation, eliminating silently ignored clicks during repeated editor recalculation.
- Restore multi-row selection for Vast.ai queue jobs and allow **Delete Selected** to remove mixed local and cloud queue entries through their correct backends.
- Keep convergence detection active beyond 1,000 Pareto results using an incremental exact 3D hypervolume sweep; set the default improvement tolerance to 0.25% without changing saved preferences or running jobs.
- Continue Vast stagnation detection after the 1 GiB cumulative intermediate-backup limit by reading a bounded metrics-only Pareto snapshot over the verified worker connection. Full result backups remain capped and final collection is unchanged.
- Disable Pareto Explorer full-result scanning when all_results.bin is unavailable, with a hover explanation that Vast.ai runs require completion and final result download.
