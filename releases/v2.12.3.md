# v2.12.3

## PBData after remote PBGui updates

- Remote PBGui updates, combined PBGui/bot updates and branch switches now
  restart PBData when it was already running. Previously these handlers omitted
  PBData, leaving its old code loaded after the checkout had been updated.
- Unit reconciliation preserves PBData's existing autostart setting. An inactive
  PBData remains inactive; updating PBGui does not opt a host into data fetching.

## PBCoinData stale process metadata and restart loops

- Recover historical registration/identity files with conflicting start times
  once both process references are positively confirmed exited. A dead PID no
  longer fails parsing before the existing exit checks can run. The normal
  guarded Start replaces the stale files; viewing status does not delete them.
- Preserve independent references and all lifetime-lock, byte-coherence, boot,
  namespace and exit checks. Live, recycled or inaccessible conflicting PIDs
  remain blocked, with a concrete reason in Services and service logs. No process
  identity tolerance or signal protection is relaxed.
- Conflicting-identity startup failures exit with status 78, which systemd does
  not automatically restart. Other crashes are limited to five starts per five
  minutes. Publication races and ordinary unresolved startup transitions remain
  retryable. Logging failures retain the reason on stderr and preserve status 78.
- Remote update handlers recognize a positively failed PBCoinData exit 78 after
  their health check and report failure without repeatedly restarting the other
  services. Start limits are not automatically reset or bypassed.
- Only PBCoinData receives the new systemd restart rules; other unit contents
  remain unchanged. English and German service guides describe recovery.

## Validation and rollout

All 1,346 focused offline process/lifecycle, update/installer, shell, release and
isolated Chromium Services tests passed. Fable assisted with planning and code
review.

No remote host was modified or restarted while preparing this release. Install
this PBGui release on the affected hosts to activate the fixes. PBData already
running is refreshed by that update; the dead-PID conflict can then recover
through the normal guarded PBCoinData start. A still-live or unconfirmed conflict
continues to require investigation rather than forced cleanup.
