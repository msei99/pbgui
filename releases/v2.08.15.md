# v2.08.15

## Fixes

- VPS monitoring caches PB8 error history and net PNL incrementally in a durable SQLite database. Existing logs are scanned once when first encountered; later collections consume only appended complete lines, and unchanged logs are not reopened. Saved offsets survive collector, API and host restarts. Cache updates are transaction-protected across processes, with handling for rotations, replacements, truncation and partial writes.
- Match archived PB8 logs by exact instance name, including run IDs and numbered rotations. Deduplicate aliases, expire hourly history after 28 days and remove obsolete cache entries.
- Fix PB8 save/move publication from secondary masters when active replicas are intentionally omitted from their replication peer lists. The background Cluster worker obtains separate authenticated capability-only replies without transferring operations or blobs along those routes. Identity, Cluster membership, freshness, unsupported-peer and retry checks remain enforced. Passive VPS nodes do not gain extra SSH fanout.

## Investigation

- On manibot50, repeated log scans were a measured contributor to resource pressure alongside bot CPU and active swapping. This release removes that repeated scanning work; it does not establish that all API timeouts or live HSL performance issues are resolved.
- The secondary-master blocker combines the PB8 rollout guard added in v1.95 with existing topology filtering. Retained manibot02 audit records contain V7 configuration operations but no PB8 publications, so they do not establish a recent PB8 regression. An older PB8 installation rejecting the moved HSL configuration on manibot62 is a separate runtime compatibility issue.

## Validation

- The test-suite gate required focused offline validation; no full suite was run.
- All 636 tests across 13 affected cache, monitor-agent, VPS, logging, Cluster, PB8 and release test files passed on the exact staged release file set. Previously hanging tests completed outside the restrictive sandbox. The logging audit also passed after documenting the existing offline worker-verification CLI's JSON stdout; local untracked research files are not included in the release.
- Regression coverage includes restart cache hits without log reads, appended/partial lines, rotation, truncation, concurrent collector processes, failed-transaction rollback and history expiry, plus secondary-master capability probes with negative identity, support, backoff and freshness cases.
- API serial 3255 exposes the release restart requirement.
- No bot/VPS deployment or runtime changes are part of this release. Resource-pressure and compatibility observations remain separate from the validated code fixes.
