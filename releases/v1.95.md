# v1.95

## Added
- Added the remaining PB8 UI parity outside Strategy Explorer: runtime-aware Dashboard forced modes, Refine Optimize Presets from PB8 backtest results, manual PB8 Cluster reconciliation preview/action, per-host profile-aware VPS bulk updates, and a separate read-only PB8 Market Data cache inventory.
- Added a combined **PB7 + PB8** VPS setup profile that enables the PB7 runner stack and installs the validated PB8 live runtime in the same Ansible setup run.
- Added PB8 live-process supervision to PBRun with runtime, assignment, version, API-key user, and optional Cluster desired-state gates; exact process identity; bounded crash backoff; and graceful process-group shutdown.
- Added PB8 remote monitor, cache, native log, and runtime-aware restart support while preserving distinct V7 instances with the same name.
- Added a separate PB8 Cluster Sync operation family with checkpoint replay, capability negotiation, and exact backed-up `data/run_v8` JSON materialization after API-key projections.
- Added PBv8 Run with the full shared PBv7/PBv8 list and editor workflows, exact local/remote runtime status, responsive sidebar filters, runtime-derived strategy metadata, coin filters and overrides, import/copy, Backtest handoffs, live logs, cookie-only browser authentication, canonical PB8 validation, atomic config-and-override bundles, optimistic version checks, explicit Cluster publication, and a rollout barrier for older state replicas.
- Added PBv8 Run backups with complete config-and-sparse-override snapshots before overwrite or delete, per-instance retention, and draft-based restore through the normal validated save path.
- Added an independent owner-only PB8 `api-keys.json` projection before PB8 config materialization.

## Fixed
- Made the shared PB7/PB8 Run config-import User field a searchable, explicitly toggleable dark-theme dropdown that opens the complete list independently of the current default selection, filters only on actual text input, and provides bounded scrolling and keyboard navigation while still rejecting unknown names.
- Blocked first-time PB7 installation on remote hosts with less than 3 GiB free disk space in both VPS Manager and the PB7 playbook, including PB8-only small VPS hosts, while retaining low-disk updates for an already validated PB7 checkout and enforcing the same gate for bulk deploys.
- Prevented PB8 Dashboard symbol actions from writing PB7-style inline coin overrides; they now update validated sparse override bundles, while ambiguous users shared by multiple PB7/PB8 instances are rejected.
- Kept the shared Refine Optimize Preset builder on HttpOnly cookie authentication when PB8 pages intentionally provide no browser token, instead of sending an empty Bearer header that masks the valid cookie.
- Kept remote PB8 updates successful on older PBGui releases whose PBRun still requires PB7: PB7+PB8 hosts retain PBRun, while PB8-only hosts stop the incompatible restart loop and report that PBGui must be updated before live supervision is enabled.
- Prevented VPS Manager's `pbgui_role` Ansible extra variable from shadowing the PB8 playbooks' registered role-probe result during remote PB8 install/update runs.
- Completed the PB8 parity audit outside Strategy Explorer: corrected VPS Manager install/update actions for PB7-only and PB8-only hosts, removed the first-install disk warning from validated PB8 updates, restored PBRun supervision and PB7 installation paths, displayed PB8 live processes, exposed the PB8 Backtest Queue controller, and enabled PB8 Backtest-to-Run/Optimize handoffs.
- Listed and loaded both PBv7 and PBv8 instances in the shared Balance Calculator with explicit version labels, validated name-based config loading, and cookie-only browser authentication.
- Restored the **Balance Calculator** and **Calc Balance** sidebar actions for PBv8 Run and routed its `/api/v8` editor base to the shared calculator API.
- Refreshed an already open PB7 Coin Overrides editor when asynchronously loaded parameter metadata arrives, and replaced silent empty sections with explicit loading, empty, or error states.
- Completed PBv8 Run parameter parity by deriving the instance identity directly from User, placing `strategy_kind` with Bot Configuration, preserving the familiar PB7 field order, showing the shared logging and live flags, moving all current PB8 live runtime additions into structured Advanced controls, and exposing PB8 logging and monitoring without losing nullable runtime defaults.
- Preserved PB8's template-default `hsl_signal_mode=coin` in the shared Run editor instead of clearing it and rejecting the first instance save.
- Made PBv8 Run strategy selection and Long/Short strategy keys synchronize bidirectionally, cache per-strategy edits, load runtime defaults for new selections, and highlight those defaults for review until edited.
- Completed PBv8 Run field round-tripping across structured controls, Long/Short JSON, and Raw JSON, including preservation of valid numeric zeroes, nullable values, and unknown runtime or JSON fields.
- Kept existing PB8 Optimize queue jobs bound to their original config when **Save & Queue** stores a queue-opened config under a new name; the renamed config now creates an independent new job.
- Enabled PBRun for PB8-only VPS profiles while keeping controller service stops and restarts from terminating managed PB7/PB8 bot processes, and hardened local and remote PB8 signaling against PID reuse.
- Added an explicit fingerprint-confirmed SSH host-key replacement action to the Add VPS preflight so reinstalled hosts can be initialized without weakening strict host-key verification.
- Installed PB8 as a second play in the VPS setup playbook so setup cannot report success before PB8 clone, virtualenv installation, and validation have completed.
- Persisted successful VPS setup completion before optional monitor and Cluster registration so concurrent inventory refreshes cannot revert the final status.
- Kept newly initialized VPS hosts in their task-log view when an older overview snapshot arrives, and completed PB8-capable Add flows from the combined setup status instead of waiting for a removed follow-up job.
- Restricted PB7 and PB8 instance targets to hosts with the matching confirmed runtime, with the same checks enforced server-side during save and restore.
- Suppressed recurring Hyperliquid API-key expiry Telegram warnings when no PB7 or PB8 live bot for the exact exchange user remains active, while retaining warnings for running or uncertain instances.
