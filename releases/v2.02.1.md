# v2.02.1

## Fixed

- Authentication: validate session file identifiers and containment, keep session tokens out of Welcome HTML and bootstrap JSON, isolate passwordless browser sessions behind shared IPs, and apply no-store/referrer headers to authentication redirects (#153, #154, #155, #156).
- Dashboard API: validate grid dimensions, safely encode inline-script parameters, and preserve position/order data when exchange candle connections fail (#150, #157, #158).
- Dashboard UI: remove duplicate template-creation refreshes, clear loading state after cancelling an unsaved dashboard, release resize scroll locks outside the editor frame, sort Income rows before first render, and scope fullscreen handlers to chart widgets (#148, #159, #160, #161, #162).
- Live trading: block deletion of observed running PB8 instances, protect credentials referenced by PB7/PB8 bundles independently of the working directory, allow stopping bots with missing or invalid configs, and support empty/template-configured Hyperliquid accounts and saved vault balances (#141, #142, #144, #151).
- Database tools: use consistent SQLite lock timeouts for schema initialization, backup copying, and integrity checks (#140).
- Income restore: replace direct live-file copying with a bounded, atomic SQLite restore from a descriptor-pinned private snapshot. Validate integrity and production schema, preserve connected readers and WAL files, and roll back unfinished failures/timeouts. Full backups now include committed WAL data and publish unique private snapshots (#152).
- Coordinate income restore with incremental history scans, local detached DB Sync, user imports, backups and local DB Tools installs through separate cross-process database leases. Only the API-owned restore reserves restart admission; detached DB Sync still survives API restart. Restore no longer stops PBData. Income deletions refuse to proceed without their safety backup.
- Optimize and backtest: give split exchange jobs distinct names, resolve relative PB8 result selectors under managed roots, and stop evaluation scans at incomplete or stalled MessagePack tails (#138, #143, #145).
- Pareto and AI: preserve configuration indices when Pareto files are skipped, rank missing metrics last, and handle non-finite response metrics and overflowing JSON numbers (#139, #147, #149).

## Security

- Address all eight findings from the follow-up review. Dashboard API, script, iframe and WebSocket URLs now use the trusted same-origin mount prefix, never a query-selected server. Dashboard messages require both the expected origin and window identity. Backtest dialogs normalize imported balances to finite numbers before HTML rendering.
- Enforce exact-origin browser checks before unsafe cookie-authenticated requests and WebSocket acceptance. Explicit valid Bearer REST clients remain supported without cookie fallback on invalid headers. Passwordless Welcome loads a non-issuing shell and creates its cookie through an origin-checked POST, including on HTTP LAN hosts. Preserve IPv6 authorities, underscore hostnames and same-origin mounted dashboards. All HTML responses, including static pages, enforce same-origin framing without removing existing CSP restrictions.
- PB8 deletion verifies exact local process identity independently of assignment/readiness and fails closed on inspection errors or uncertain remote state. Snapshot rows carry their own atomic generation/freshness stamps; new diagnostics cannot authorize old stopped rows. Optimizer deletion accepts only complete top-level runs, including in batch requests, while nested artifact reads remain supported.
- Validate SQLite schema objects before integrity expressions execute and enforce parsing/allocation limits. Reject triggers, views, virtual tables, unsupported expressions and quoted-keyword constraint bypasses; verify parsed main-schema constraints on both Income and DB Tools restore paths. Local DB Tools backups have busy-inclusive deadlines, run outside the API event loop, and drain owned workers before cleanup. Snapshot publication uses collision-resistant names and directory fsync.

## Validation And Limitations

- Added isolated offline regression coverage for the issue batch and updated the relevant English/German guides. Full offline suite: 6,924 passed, 41 skipped. Targeted security follow-up found no remaining concrete finding in the reviewed fixes. Coverage includes hostile origins/messages/HTML, HTTP LAN and IPv6 bootstrap, static-page framing, PB8 observation publication races, destructive path boundaries, hostile SQLite schema, retained WAL readers, cross-process locks, rollback, worker cancellation and restart admission during detached sync.
- #146: verified that current balance writes replace prior user balances and clean up legacy duplicates; added ADG regression coverage without changing its calculation.
- After installing the restore fix, reload both the API and PBData before using it, and allow older detached DB Sync workers to finish so every writer uses the new coordination. No running services were restarted during development. The existing remote DB Tools installation implementation is unchanged.
- The monitor service must also load the new collector code before remote PB8 deletion can use generation-bound observations; legacy unstamped observations intentionally block deletion. Browser framing and deployed reverse-proxy behavior have not been tested in a real browser. SQLite deadlines are cooperative and cannot guarantee a hard limit for a stalled operating-system file operation.
- Browser fullscreen and cross-frame resize behavior is covered with test doubles, not a real-browser smoke test. GitNexus CLI and MCP were aligned on version 1.6.11 and the index rebuilt with PDG; impact, API impact, change detection and taint queries now work without the former schema mismatch. The aggregate change scan reports CRITICAL impact across shared authentication flows; static-analysis coverage limits still apply.
